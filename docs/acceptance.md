# 首版验收报告

2026-11-14，Claude Code 2.1.312。结论：工具结果保护的实现与合成回放验证完成；全入口保护及严格上下文兼容性未完成，已于同日后续完成用户级自动加载安装，当前启用工具结果配置。

## 证据

- 检测核心 35 项测试通过：STUN、公私网 IPv4/IPv6、zone、Fake IP、SSH 来源、设备序列号/UDID/MAC、用户路径、邮箱、代理认证、错误信息、嵌套 JSON、ANSI/Unicode、配置迭代、超限及正常反例。
- Claude 原生 Mods 测试 11 项通过（含性能测试）：工具输入拒绝、输出扣留、异常、未初始化、MCP、上下文、并发、非法配置及后续推理短路。
- 本地模型桩 + 真实 CLI 共 24 组：22 组基础/历史内容回放，加实际 stderr 失败和严格上下文启动诊断。
- 无插件对照：2 次请求，第二次用户消息中的 tool_result 含测试 IP。
- 工具结果配置：敏感回放只有首次请求，没有包含结果的第二次请求；干净输出继续发送第二次请求并完成。
- 严格上下文启动诊断：0 次请求，普通提示也被拒绝。这是已知兼容性失败，不计为“干净任务正常运行”。测试中固定断言这一限制，防止它被遗漏。

真实 CLI 回放通过 Bash 执行 base64 解码，模拟返回历史内容形状；MCP JSON、设备命令和跨代理消息均为虚构输出，不连接真实 NAS/手机/MCP 服务。实际 stderr 用失败退出的 Bash 命令产生。原生 Mods 的 MCP 事件测试与上述回放分开计证。

首次扩展回放发现 JSON 包裹 ANSI 地址漏检，修复了 Unicode 解码与 ANSI 处理顺序，新增回归样本。所有报告仅包含合成数据，机器可读结果保存在被 Git 忽略的 benchmarks/results/。

## 性能

默认 7 条规则（其中 1 条禁用）、正常文本负载。本机重复测量，单位毫秒：

| 范围 | 100 KB p95 | 1 MB p95 |
| --- | --- | --- |
| 纯检测核心 | 约 1.1 | 约 10.5 |
| Claude 原生测试框架内工具事件到返回 | 约 2 | 约 12–13 |

原生测试框架测试含事件调度与结果处理，不包含真实模型网络等待，也不是生产运行完整开销的对照差值。未验证 2000 条规则、10000 个匹配值和全部 8 路并发性能目标；较大规则集可能触发 100 ms 扫描预算而阻断。不能将当前数字推广到所有配置。

## 发布限制

严格模式对自动上下文的宽泛规则存在兼容性问题。工具结果配置有明确的较窄范围；不得宣称环境、记忆、附件、遥测全部被覆盖。后台代理取消、worker 崩溃、宿主超时降级、禁用/卸载插件和完整会话恢复尚缺真实链路验收，因此不声称系统级失败关闭。

规则更新采用新会话生效和原子文件替换；热切换与持久审计未实现。未修改用户现有 Claude 配置，没有把历史备份中的真实敏感值复制到项目。

插件本地结构验证通过；公开插件目录的发布检查仍缺 LICENSE 和图标，本轮未发布到 marketplace。

## 用户级自动加载

本机 `agent-safeguard@agent-safeguard-local` 已安装且 enabled 为 true。用户级配置由 Claude 官方 CLI 写入，修改前的设置文件备份在项目忽略的 local/pre-user-install-* 目录。

自动加载验收使用实际安装登记及安装源，在隔离 HOME 中仅复制本插件注册信息；没有 --plugin-dir 或专用启动器，没有复制账号凭据。使用本机模型桩比较干净结果、敏感结果和错误输出。桌面 Code 按官方共享配置机制覆盖，未在 App UI 中发起真实模型请求。普通 Chat 和 Cowork 不属于本次安装覆盖范围。

自动加载实测四组全部通过：无插件敏感对照 2 次请求且结果上送；已安装插件敏感输出 1 次请求；干净输出 2 次请求；stderr 敏感错误 1 次请求。记录在 benchmarks/results/installed-e2e.json。

## 0.1.1 启动时序修复

用户反馈桌面端首次输入被拒绝，但随后状态显示 ready=true、blocked=false、lastRule=null。实际 App 日志显示桌面端使用 2.1.325，之前终端验收使用 2.1.312；单靠这份反馈无法确定实际会话的完整事件顺序。

新增原生测试重排启动事件，证明 0.1.0 在 prompt.submit 早于 session.start、或 prompt.section 早于配置加载时会错误拒绝正常提示。0.1.1 让这些入口等待共享的初始化 Promise，先读取实际配置，并且不让迟到的 session.start 清除已有敏感结果阻断。没有启用 prompt.context 规则时，不对该未覆盖入口应用内容格式限制。

同时纠正了原生上下文测试的输入字段：应使用 name/text 而非 section。旧测试会因错误事件形状走异常阻断，不能当作规则检测上下文内容的有效证据；纠正后的测试已验证真正的内容命中。

状态命令新增插件版本和最后事件，提示词拒绝原因区分初始化失败、规则命中和会话锁定，不回显原始内容。配置版本仍为 0.1.0-tools，与插件版本 0.1.1 分开管理。规则没有被关闭或放宽。

修复验收：35 项核心测试、14 项原生测试通过；使用桌面端 2.1.325 可执行文件和已安装插件进行四组本地请求对照，正常输出继续、敏感结果及 stderr 仍停止后续请求。用户级安装记录已更新为 0.1.1；尚待用户在原 App 界面重启后确认实际症状消失。

## 0.1.2 用户路径放行

按用户明确要求，用户路径属于正常编程上下文：删除 personal-environment 内对 /Users/ 和 /home/ 的自动阻断，覆盖用户提示词、工具返回及启用了上下文检查的入口。没有为整条消息增加 allow 例外；同一内容仍依次检查 IP、凭据、设备标识、邮箱、主机名及个人精确规则。自定义精确值规则若另外指定路径仍按用户配置生效。

核心测试 40 项、原生 Mods 测试 17 项通过。已安装的 0.1.2 使用桌面引擎 2.1.325 完成六组真实 CLI / 本地模型桩测试：用户路径提示词及路径输出产生正常的第二次请求，路径与敏感 IP 混合的输出仍不产生第二次请求。实际安装已更新，现有会话需重新加载或新建后生效。

历史报告中的“用户路径会被阻断”是 0.1.0/0.1.1 的旧策略，不代表 0.1.2。所有测试路径均为虚构样本。

0.1.2 完整回放中的严格上下文诊断仍不能完成普通任务，但由旧版首次请求前阻断变为首次请求后阻断。该配置并未启用，仍不能当作全入口兼容性通过。测试更新这一已观测基线，工具结果保护的正常及敏感请求断言保持不变。


## 0.1.3 邮箱放行

按用户明确要求，删除 personal-environment 内的邮箱自动检测；保留主机名字段检测。邮箱与用户路径本身不再导致拒绝，不为整条消息增加豁免；同一输出中的 IP、凭据、设备标识及自定义精确规则仍继续检查。

核心测试 43 项、原生 Mods 测试 19 项通过。桌面引擎 2.1.325 加用户级实际安装完成八组真实 CLI / 本地模型桩验收：邮箱提示词和 Git 作者、共同作者输出正常产生第二次请求；邮箱与合成密码混合的输出停止在第一次请求。此前路径、IP、stderr、干净输出和无插件对照全部通过。

用户反馈的 Git 命令各段在原工作区只读重放，结果仅在内存送入已安装检测器，各段及合并结果均放行；未保存或回显原始作者、提交内容。用户级插件更新为 0.1.3，规则配置未覆盖。已有会话需新建或重新加载插件后生效。

## 0.1.4 本机及内网地址放行

按用户明确要求，在 IP 检测器增加可配置的 excludeCidrs，默认网络规则采用 README 中的 13 个网段/地址。本机用户级配置仅合并 network.address 的豁免列表并更新规则版本为 0.1.4-tools，其他规则保留；旧配置自动备份为安装目录 local/rules.previous.json。加载时校验、预编译 CIDR，计入匹配值上限；逐地址排除，仍检查其他地址及所有其他规则。IPv4 映射 IPv6 按内嵌 IPv4 处理，防止映射公网地址被整段放行。修正 MAC 表达式边界，避免 IPv6 内部的连续双位分段误命中 MAC。

47 项核心测试、21 项原生 Mods 测试通过，覆盖范围首尾与相邻地址、zone、映射地址、嵌套 JSON、配置撤回/非法网段/数量上限、其他精确规则和混合敏感输出。已安装插件 0.1.4 加桌面引擎 2.1.325 的 11 组本地模型桩请求测试全部通过：内网提示词和结果正常产生第二次请求，内网混合映射公网 IP 或密码的结果只产生首次请求；旧路径、邮箱及错误结果测试通过。

反馈中的代码读取/模拟器列举命令在原工作区只读重放，结果仅在内存检查，完整输出通过，未回显或保存原始输出到项目。纯检测基准正常文本 100 KiB p95 约 1.18 ms、1 MiB p95 约 11.58 ms；原生测试框架 1 MiB p95 约 11 ms。此为本机合成负载，不代表所有地址密度、规则规模或生产完整链路延迟。插件结构校验通过；公开目录发布限制仍同前。

新会话加载后应显示 pluginVersion=0.1.4、ruleVersion=0.1.4-tools。历史报告中“私网、链路本地、Fake IP 阻断”是旧策略，当前以 README 清单为准。


## 0.1.5 项目统一更名

项目目录、npm 包、启动脚本、插件 manifest、用户级安装目录和本地 marketplace 统一使用 agent-safeguard；状态命令改为 /agent-safeguard-status。现有用户规则与上一版规则文件完整复制，校验当前规则逐字节一致，ruleVersion 仍为 0.1.4-tools。官方 CLI 已卸载旧插件登记、移除旧 marketplace，新插件 agent-safeguard@agent-safeguard-local 在 user scope 启用，避免新会话重复加载。旧安装源和变更前设置备份归档于忽略的 local/ 中。

47 项核心测试、21 项原生 Mods 测试、11 组桌面引擎真实 CLI / 本地模型桩自动加载回放通过，结构校验成功。第一次原生性能测试在 1 MiB 干净输出时被扣留，未获得该次具体内部原因；本机已有 100 ms 扫描预算可能受调度影响，随后原样重跑 21 项全部通过，未放宽预算或修改检测行为。这一情况继续作为性能限制记录。

当前只实现 Claude Code 适配，更名不代表已支持其他 Agent。新会话加载 0.1.5；保留 SAFEGUARD_BLOCKED 错误标记及 SAFEGUARD_ 测试环境变量接口。
