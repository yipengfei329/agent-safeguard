# 一期设计

状态：目标规格。首版已实现其中的工具结果和部分上下文控制，实际完成范围及测试证据见 [验收报告](acceptance.md)。设计基线为 2026-11-14 本机 Claude Code 2.1.312；本文未完成的热切换、持久审计和全入口验收仍是后续要求。

当前策略调整（0.1.4）：用户路径和邮箱本身不再触发自动拦截，本机和常见内网 IP 按 README 的 excludeCidrs 清单放行；保留同一内容中其他 IP、凭据、设备标识、主机名等检测。以下历史设计中的路径和邮箱保护要求以此调整为准；自定义精确值或域名规则仍按配置生效。

## 产品定义

Agent Safeguard 是本地内容检查插件。第一期针对工具返回的文本和结构化数据，在交给模型之前执行可配置规则；命中后扣留整份结果，并停止受影响会话的后续模型请求。正常结果保持内容和顺序，不向提示词追加检查说明。

保护对象包括 IP、私有网络和服务地址、设备标识、账号身份及凭据。保护的是会话内容中的信息；请求的网络出口 IP、服务器已接收的历史内容和账号处置原因不属于这个控制点。工具输出是重要入口，用户粘贴、项目指令、记忆和自动环境注入也是入口，不能只拦 Bash。

目标优先级：不释放待检查结果 → 正确阻断 → 可解释的规则迭代 → 低延迟。不以检测超时后放行为性能优化。

## 接入能力和交付边界

采用 Mods 适配层，不把传统 PostToolUse 的 block 当作结果过滤器。官方文档支持在 tool.call 的 next 返回后以 deny 扣住结果；工具的外部副作用已经发生。异常处理必须显式设计，默认异常行为可能保留原结果。[官方事件说明](https://code.claude.com/docs/en/plugins/mods/events)

当前版本已用隔离临时插件做静态检查：tool.call、turn.step、prompt.submit、prompt.compose、prompt.section、prompt.context、prompt.attachment、session.append、session.compact 和 $.turn.abort 均被本机验证器识别。该检查没有加载插件、执行工具、调用模型或证明拦截成功。运行时以本机生成的类型声明为准。[本机类型和验证流程](https://code.claude.com/docs/en/plugins/mods/create)

| 控制点 | 一期用途 | 发布前必须验证 |
| --- | --- | --- |
| tool.call 之前 | 检查工具输入；拒绝已知敏感文件读取和高风险操作 | 内置工具、MCP、子代理均被覆盖；输入规则不会被别的插件改写绕过 |
| tool.call 返回之后 | 检查成功、失败、stderr、嵌套文本；扣住原始结果 | 原始结果未出现在下一次请求、摘要或旁路上报中 |
| turn.step 之前 | 检查阻断状态；阻止后续推理，包括子代理 | 不是只隐藏 UI；不能调用 next 后再判断 |
| prompt 系列入口 | 检查用户文本、指令、环境、记忆及注入文本 | 列出实际覆盖字段；未知入口不能标记已保护 |
| 会话保存、恢复、压缩 | 防止敏感结果经记录、摘要、重试重新进入上下文 | 保存时机、resume、branch、compact 和背景任务分别验收 |

turn.step 不是完整 HTTP 请求体。官方当前引擎 http.fetch 接口要求 2.1.321+；内置 guard 加载时，非组织管理的 mod 收不到这些引擎事件。因此本机普通用户插件不能按“拦截每一个最终 HTTP 请求体”设计。[官方接口及限制](https://code.claude.com/docs/en/plugins/mods/reference#fields-on-claude-codes-own-httpfetch-requests)

第一期支持范围必须由验收清单生成：未验证的 Claude Desktop 普通聊天、服务端工具、附件上传、遥测、直接网络请求不能自动归入范围。若用户要求所有请求都必须检查，而当前接口做不到，这属于架构阻塞；应评估受支持的请求网关或客户端改造，不能以增加规则代替缺失的控制点。

自动环境常含用户路径，严格扫描可能在第一条请求前就阻断。原型需要验证能否抑制非必要的敏感注入；对工具寻址必需的真实路径，不默认替换成占位符。隐藏所有环境信息与保持原有执行行为可能冲突，这种入口不能用静默放行解决，必须明确限制范围或使用经过验证的隔离工作区方案。

## 执行路径

```text
加载可信规则并预编译
        ↓
工具输入检查 → 命中：拒绝执行并停止当前轮
        ↓ 通过
原工具执行
        ↓
结果暂存 → 文本和结构解析 → 本地规则检测
        ├─ 通过：原样交回
        └─ 命中或无法检查：扣留结果 + 设置阻断状态 + 停止当前轮
                                                       ↓
                               每次后续推理开始前再次检查阻断状态
```

“阻断这一次请求”指不发出包含该结果的下一次模型请求。产生工具调用的上一轮推理已经完成，无法撤回。模型生成的分析里出现敏感值，也说明值可能已经到达模型；过滤分析只能减少后续传播。

命中时先同步设置会话阻断状态，再执行停止动作。使用固定安全原因，如 SAFEGUARD_BLOCKED 和规则编号；不把命中的值、截取片段、文件路径或异常原文放到错误消息中。阻断提示只需告诉用户信息类别、工具和可采取的本地处理步骤。

不自动重试工具，不自动把敏感内容改写后继续推理，不自动执行“再运行一次看看”。一期整份扣留；局部脱敏会改变代码、配置和诊断语义，后续只能在明确支持的结构中提供。

## 状态与并发

适配层维护会话及代理标识、规则快照版本、未完成检查计数、阻断状态。每个结果都先检查后交回，不能为等待多个工具完成而提前释放部分未检查内容。

一个结果命中后，该会话中的新工具调用、子代理启动及后续推理均不得继续；主轮停止 API 是否同时停止后台代理须实测，不作假定。已经发送出去的请求无法撤回，正在执行的外部命令也不保证能撤销。并发安全的验收条件是敏感结果从未被交回，而非声称所有已在途操作都能即时取消。

新轮开始不能自动清除阻断状态。恢复需要用户在本地确认处理结果，并重新检查仍将进入上下文的内容；不允许模型通过提示词、工具或项目配置自行解锁。首版不提供“放行这份原始敏感结果”的快捷操作。

热重载、进程重启、resume 或缺失状态不能视为安全：先恢复校验，再接受新的推理。无法取得完整待发送上下文的历史会话不标记为完整保护；首版优先支持从启动时已受保护的新会话。

## 规则模型

规则引擎与 Claude 适配层分离，纯本地运行。JSON 配置负责选择检测器、检测范围和动作，不允许配置执行 JavaScript 或 shell。内置检测器属于代码能力，新 IP、域名、精确值和检测范围属于数据更新。

| 检测器 | 检测内容 | 误报处理原则 |
| --- | --- | --- |
| ip | IPv4、IPv6、CIDR、URL 内地址、带端口/zone 的地址 | 用地址解析校验，不把公网地址自动归为用户地址；支持全部地址或指定网段 |
| exact | 用户本地登记的具体敏感值 | 默认区分大小写；不把真实值放进仓库或日志 |
| domain | 用户域名和子域名 | 按域名边界匹配，不能把相似后缀当同一个域名 |
| credentials | 私钥、带认证 URL、凭据字段和已支持的 token 格式 | 采用具体结构；单独出现 password 一词不算已泄露密码 |
| device-identifiers | 序列号、UDID、硬件 UUID、MAC 等字段和已知格式 | 结合字段或设备诊断上下文；普通 UUID 不一概等同设备标识 |
| personal-environment | 用户主目录、主机名字段、账号邮箱、系统诊断结构 | macOS、zsh、Surge 等软件名本身不自动认定敏感 |

当前默认结果策略：识别出的 IP 按 excludeCidrs 排除本机及常见内网地址，清单以 README 为准，其余地址阻断。将 ip 模式显式改为 cidr 是用户选择的较窄保护，不得仍声称覆盖全部 IP。工具输入与返回值的规则范围分开，避免把正常访问本地地址一概当作新的结果泄露。

输入扫描只能阻止工具接收参数或进一步外发；若参数来自云端模型，扫描发生时模型已经知道这些参数。对敏感文件的读取应尽量在执行前限制，但文件路径策略不能替代结果检查。

内置规则包与用户私有配置分别版本化。每条规则有稳定 id、enabled、sources、可选工具范围、detector 和 action。action 仅有 block 与 observe；observe 只记录类别，不算防护。优先级为任何 block 命中即阻断，不存在一个 allow 使整条结果跳过其他规则。

一期用范围收窄和显式调整规则处理误报；逐匹配例外留给后续设计，必须限制规则 id、来源、匹配值和有效期。禁止“信任 Bash”“这个仓库全部放行”一类宽泛例外。

配置格式见 [规则示例](../config/rules.example.json) 和 [配置 Schema](../schemas/rules.schema.json)。示例只有虚构数据，首版已实现配置校验和加载。结构 Schema 之外还须语义校验重复 id、未知检测器、非法网段、空匹配值、资源总量及工具范围；加载前限制配置文件总量为 1 MiB，编译也设资源预算，不能等构造巨大对象后才拒绝。

## 配置加载和迭代

1. 安装包携带内置规则；用户私有值保存在受控的本地目录，开发期为已忽略的 local/，不读取当前仓库自动提供的放行规则。
2. 启动时读取、校验并编译一次，形成不可变快照。调用路径不读磁盘、不下载规则、不向模型请求判断。
3. 更新依次经过结构和语义校验、正反例回归、性能检查，再在当前轮结束且没有待检查结果时切换快照。不会在一个工具批次中混用版本。
4. 新配置错误时保留已验证旧版，并明确提示更新未生效；首次没有有效规则则不能进入受保护运行状态。版本号不能代替实际内容摘要。
5. 规则更新导致覆盖范围扩大时，旧的“通过”缓存全部失效；当前上下文重新检查，不能只检查下一条新结果。无法完整重验则要求新的受保护会话。
6. 每次发现遗漏，先加虚构的最小复现样本，再修规则或检测器，补一个近似但无敏感信息的反例，最后发布规则版本。升级和回滚都显示生效版本。

可信用户才能安装或调整规则；插件规则目录不能由模型工具随意写入。普通插件不能抵抗拥有同一用户权限的恶意代码，文件权限、宿主的受保护目录和能力检查共同限定信任边界。更新文件的原子替换应由安装/管理组件完成，不能假定 Mods 的 fs.write 是原子的。

## 解析和资源限制

扫描实际进入模型的文本字段及结构化字段，包括 stdout、stderr、错误对象中可见的字符串、MCP content、JSON 字符串和跨工具转述。路径、键和值都可能携带信息。不能只扫描最外层 text，也不能只看成功结果。

内置规则对原文与有限规范化文本检查：识别 ANSI 转义、正常 JSON 转义、URL 地址表达；嵌套 JSON 最多再展开两层，展开后的字节和节点计入总限额。不是任意编码解密器，不承诺发现隐藏在任意 base64、压缩包、图片或恶意混淆中的数据。

建议起始上限：单次待检内容总量 4 MiB、结构深度 64、节点数 100000、规则数 2000、总匹配值 10000；超过上限则扣留并提示，不截断后放行。上限包括错误输出、解码副本与分片累计量，具体数值由基准结果调整。

分片只有在完整拼接和检查后才能交回；内部按块扫描要保留边界状态，IPv6 和精确值跨块也必须识别。不能无限缓存后台输出；超限终止并扣留。普通结构化 JSON 中相邻无关字段不任意拼接；对于需要跨字段重建的已知协议单独加适配。

图片、音频、PDF 二进制和未知结果格式没有通过文本检查的资格。严格模式下遇到这些内容先阻断；后续可增加本地提取器，但提取失败同样不能放行。附件在到达插件之前是否已经上传，必须单独验收。

## 失败行为

| 情况 | 插件内行为 | 系统限制 |
| --- | --- | --- |
| 规则命中 | 扣留、设置阻断状态、停止当前轮 | 不撤销已完成的工具副作用 |
| 解析错误、超限、未知格式 | 按无法检查处理，阻断 | 不保证发现任意混淆内容 |
| 检测器抛错或超时 | 显式 catch 返回安全拒绝并阻止后续推理 | 不把宿主默认异常行为当作阻断 |
| 主回调和 catch 均失效、worker 崩溃 | 必须测试宿主是否继续；不通过则不发布失败关闭承诺 | 普通 mod 未必能约束宿主降级行为 |
| 插件被禁用、没有加载 | 启动检查不得显示已保护 | 不存在的插件无法自行阻止宿主运行 |
| 规则更新失败 | 旧版本继续生效，明确状态 | 没有旧版本则拒绝受保护启动 |

扫描自身设定较短的资源预算，预编译并采用有界算法；不依赖最终宿主超时来中止复杂正则。不能在 catch 中为获得结果再次 next，也不能错误地把已取得的原始结果返回。

## 性能与部署

第一期用 JavaScript/TypeScript Mods 适配层与检测核心，无常驻服务，无开机自启动，无每次启动子进程、OCR、远端模型或在线 IP 查询。Rust 仅在基准显示扫描核心是瓶颈后评估；Mac 管理界面不在一期关键路径。

IP 用解析器，精确匹配采用预编译索引；多规则共享词法扫描，避免每条规则完整遍历一次正文。初版不接受用户任意正则；需要时选可保证线性复杂度的实现。对已检查且不变的对象可记录规则版本与检查状态，但不能仅凭工具名或会话位置缓存通过结果。

| 大小 | 完整拦截额外耗时目标 |
| --- | --- |
| 10–100 KB | p95 ≤ 5 ms |
| 1 MB | p95 ≤ 20 ms |
| 4 MiB 和并发负载 | 测量 p50/p95/p99、峰值内存、队列等待后决定限制 |

这些是预算，不是实测。分别测纯扫描和包含 Mods 调度、序列化及跨 worker 通信的总开销；比较插件开/关的同一合成负载。覆盖 100 与 2000 条规则、10000 个匹配值、1/4/8 个并行工具、无命中及末尾命中。不能以一次字符串正则微基准证明整体速度。

安全结果原样返回，不额外生成模型 token，不每轮重写系统提示词，避免无谓破坏提示词缓存；首次完整检查、规则更新和恢复校验允许单列开销。“不影响执行链路”定义为正常受支持内容保持行为、开销有界；命中、未知格式和无法检查时中断是预期行为。

审计仅本地保存时间、规则 id、工具类别、配置版本、大小与耗时，不保存原文、敏感值或可枚举 IP 的普通哈希。日志异步且队列有界；丢弃日志不能导致内容放行。限制日志文件权限并设轮转。

安装前先 --plugin-dir 隔离验收，再提供用户级安装。项目名、命令与插件 manifest 统一使用 agent-safeguard，当前提供 Claude Code 适配。启动状态显示版本、规则版本和已验证的覆盖能力，不把静态配置存在当作成功加载。

## 发布门槛

第一步是接口可行性原型，优先于规则数量和 UI。使用虚构 canary 及隔离的本地模型响应桩，检查实际收到的请求字节；不把真实凭据或历史会话接入测试端点。模组单元测试证明局部行为，真实 Claude 执行链路证明时序，两者都要有。

必须覆盖：Bash stdout/stderr、Read/Grep、MCP 嵌套文本和错误、子代理前后台与恢复、并行结果、分片末尾、超大结果、图片和未知格式、检测抛错与超时、宿主降级、规则错误与热更新、旧会话恢复和压缩、记忆和环境自动注入、其他插件的顺序、被禁用和未加载。

验收断言：敏感 canary 未出现于受测出站请求；命中后未再发起受影响代理的后续推理；干净结果保持原值与行为；未检查内容不能显示为通过。审计日志、调试日志及错误提示也检查无原文回显。遥测与附件上传路径若无法观测，明确列为未覆盖，不能宣称全云端防护。

任何一个关键用例失败，先解决控制点或缩小并明确交付范围，不能通过禁用断言、静默放行或仅隐藏界面完成验收。
