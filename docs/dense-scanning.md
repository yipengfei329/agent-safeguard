# 0.1.24 密集代码扫描

本轮同时包含通用 Token 的词形误报修复（见 `credential-detection.md` 的 0.1.23 记录）和密集代码性能优化。100 ms 检测预算、4 MiB 文本上限、超时阻断与扫描完成后才交付结果的行为均未放宽。

## 开销与修改

此前每个字段检测器各自解析整段源码的类型上下文，词法循环逐词、逐标点执行；同一候选值还会重复经过字面量解码、表达式与值形态判断。密集代码在本机原生 Mods 引擎中可耗尽预算。

- 同一文本节点内，凭据、设备与主机名检测共享一次已完成的类型解析。只按文本完全相等复用；模拟器掩码改变文本后重新解析；未完成或超时的结果不发布。
- 类型扫描在声明外只寻找类型头、字符串、注释和正则字面量；声明内只处理字段起点和花括号。保留声明边界、嵌套深度上限和完整性要求。长空白先原生裁剪，避免尾部正则反复回溯。
- 无转义字符串使用原生查找定位结束符；有转义、未结束、原始及三引号字符串继续使用原有语义。显式字面量赋值及明确的成员引用减少不需要的上下文解析。
- 重复候选缓存包含字段匹配全文、前方最多 256 字符及右侧最多 1,024 字符，并保留类型成员的逐次检查。每个检测器每次扫描最多缓存 128 项；满后累计未命中达到 128 次即停止构造缓存键。它不会跳过相邻字段、整行或整文件，也不会跨扫描复用。
- 短词形标签在通用 Token 值检查的前段判定，减少后续无效计算；密码字段与独立密钥格式仍走原有保护路径。

## 验证口径

`fixtures/dense-source.mjs` 提供重复和逐行唯一两种源码；同时含凭据、设备和主机字段的声明、引用与调用。原生测试覆盖 10 KiB、100 KiB、1 MiB，6 条启用规则，并发 1 / 4，每组预热 5 轮后采集 20 / 80 个样本。统计覆盖完整原生工具结果 hook；并发耗时包含同一运行时的排队，不能把四个请求的累计耗时与单次扫描的 100 ms 预算直接比较。

检查包括：跨语言提取矩阵、类型头边界、注释/字符串/正则、不完整声明、转义与拼接、缓存上下文变化、相邻敏感值、结构化数据、独立格式，以及 1 MiB 唯一值源码末尾的凭据。末尾凭据测试同时覆盖正常输出和错误输出，断言命中 `security.credentials`，而非仅因 `inspection.failed` 被扣留，并断言后续模型分发次数为零。

`npm test` 与 `npm run test:mods` 按测试文件串行运行，避免多个独立性能测试进程互相抢占同一个墙钟预算；文件内的并发调用测试保留。此前直接并行运行所有原生测试时，在本机其他编译/模拟器任务负载下仍观察到超时，包括小输出场景。保留预算意味着无法承诺宿主被长时间抢占时绝不超时。

```sh
npm test
npm run test:mods
node benchmarks/dense-native.mjs
# 对照预先保存的旧版 bundle；其他 hook、样本和规则相同
node benchmarks/dense-native.mjs /absolute/path/to/baseline-core.js
SAFEGUARD_TEST_INSTALLED=1 python3 scripts/e2e.py
```

对比探针每个场景使用独立的插件测试实例。一旦扣留结果，立即停止该场景并标记未完成，不把会话锁定后的快速拒绝计为扫描性能。原生测试模拟宿主调用，实际安装后的请求记录另行验证；其中密集 Bash 输出用 10 KiB 样本，不能冒充实际 Bash 1 MiB 全链路测试。

实测数据见 [dense-scan-measurements.json](dense-scan-measurements.json)。所有样本均为虚构数据，数字是本机观测，不是通用性能承诺或公开准确率基线。

## 本次结果

Apple M2 Max、本机原生引擎，完整 hook 单并发延迟（毫秒）：

| 1 MiB 样本 | 优化前 p50 / p95 / p99 | 优化后 p50 / p95 / p99 |
| --- | --- | --- |
| 原有凭据/类型混合源码 | 85 / 89 / 92 | 31 / 32 / 32 |
| 多字段重复源码 | 预热阶段超时 | 36 / 40 / 41 |
| 多字段逐行唯一源码 | 预热阶段超时 | 52 / 57 / 58 |

对照采用已保存的 0.1.23 本地 bundle（已包含本轮词形误报修复），以隔离性能改动的影响。0.1.24 的全部 18 组测量均完成，无预热或采样阻断；并发 4 的完整分位数在 JSON 中，包含排队时间。核心 2541 项、原生 107 项回归均通过。此前高负载并行文件测试中的超时不作为通过结果，上表采用隔离运行的同一探针；100 ms 失败关闭策略仍可能因宿主调度延迟触发。

本机安装已更新到 0.1.24，缓存内引擎、hook、manifest 与构建产物一致，个人规则哈希未变。82 个实际安装请求场景全部通过：密集正常/错误输出均产生后续请求，末尾凭据场景只有首个请求；桌面后端 14 项测试通过。原报错片段仅在本机内存中复测，已放行，未复制到样本或报告。已有会话需重新启动加载新版本。
