# 脱敏与恢复：实现验收记录

日期：2026-11-16。插件 0.2.0，桌面 0.3.0；本机 Claude Code 2.1.325，macOS arm64，Node 26.10.0。样本均为虚构，未读取其他项目的实际 IP、密钥、设备或订阅数据。请求回放使用隔离 HOME 和本机 HTTP 模型桩，不向外部模型发送测试数据。

本轮完成 P0–P4 的首批支持路径与 P5 的本机隔离验收。真实用户配置迁移随后经用户授权完成，见文末安装记录；Hermesh/Claude 桌面活跃会话试用、跨平台验收及正式发布尚未执行。P6 的凭据/设备/主机名脱敏不在本次实现范围。

实现及操作见[使用说明](recovery-redaction.md)，机器可读的场景结论及全部分位数见[测量数据](recovery-redaction-measurements.json)。不能把这份范围内的通过结论扩展到所有插件或宿主路径。

## 关键场景与断言

| 场景组 | 代表 case | 必须满足的断言 |
| --- | --- | --- |
| 地址与位置 | IPv4、IPv6、mapped IPv6、zone、端口、句尾、Unicode 前缀、Unicode 转义、ANSI 插入 | 原位置正确替换，排除网段仍保留；原值不因偏移错误残留 |
| 重复/结构 | 同值多次、数组、嵌套 JSON、多层结果包装 | 同实例同值同标签；所有表示重检；输入对象不被修改 |
| 歧义/结构风险 | 敏感 JSON 键、重复键、损坏 JSON、源码、命令、仅有裸地址、循环结构 | 无可靠替换时扣留，不选择性返回剩余片段 |
| 规则冲突 | IP 与自定义 exact 重叠、IP 邻接凭据/设备/主机名、说明文本命中规则 | 原始 block 规则优先，不被先行脱敏隐藏；说明也必须通过复检 |
| 输出适配 | Bash 成功、stderr 失败、Read/MCP、持久化路径、后台句柄、未知字段 | 去除 raw ref；失败保持 is_error；未验证输出形态不替换成成功 |
| 消息入口 | composer、bridge、sdk；插件、peer、通知、meta、command、来源缺失 | 仅选定可信入口可触发恢复；输入自身命中可以修改后重发 |
| 并发/生命周期 | 四路调用、32 个调度种子、待完成 turn、存活子代理、旧代理回调、旧 step、自动根轮次 | 未完成时不能恢复；旧代际无新代际授权；会话结束不可恢复 |
| 故障 | 限额、过期截止时间、标签满额、上下文阻断、后续故障覆盖、健康检查 | 故障不被普通消息清除；上下文门禁保持；健康检查不释放旧输出 |
| 多次拦截/控制 | 连续暂停与恢复、下游提示拒绝、压缩暂停门禁 | 多次拦截独立归档；拒绝不留下永久 grant；暂停时不压缩 |
| 配置迁移 | 草稿独占创建、0600、ID/来源保留、自定义规则、无效选择、旧安装、apply/rollback | 不隐式覆盖真实规则，不改变输入 block，错误不打印规则正文 |

原生子代理/MCP 事件覆盖不等于真实远端 MCP、后台子代理请求链路验收。自动根轮次限制保证恢复授权不任意传递，也可能限制无新用户提示的自动续跑。

## 真实请求与历史证据

新脚本 `scripts/e2e-recovery.py` 让模型工具参数只引用合成本地文件路径；敏感样本由测试进程写入文件，不预先出现在模型工具参数中。采集真实后续 Messages API 请求，并解析实际 `.jsonl` 历史；检查同时处理 Unicode 转义和 ANSI，不只搜索界面文字。

26 个场景包括 clean、IP 重复、IPv6、mapped、转义、ANSI、JSON、数组、嵌套 JSON、Unicode、stderr、凭据、stderr 凭据、stderr 源码、混合敏感值、源码、裸地址、重复键、敏感键、输入拒绝、legacy 锁定、block/redact 重叠、Read 回退，以及插件缺席/禁用两组对照。

- 支持的脱敏结果：原轮次发生两次模型请求，第二次包含代号及提示；合成受保护原值在已检查的请求和工具结果历史中不存在。
- 必须扣留：原轮次只有第一次模型请求，工具结果没有引发下一次推理；安全新消息随后可以在同进程继续。
- 输入拒绝：首条没有模型请求，安全修订可继续；用户输入可能已被宿主本地历史保存，故不声称其本地历史无原值。
- 旧配置：同进程依然锁定，确认没有静默改变兼容行为。
- 错误输出：真实请求中保持 `tool_result.is_error: true`，并能继续分析；成功输出不伪造错误状态。
- 24 个受保护/兼容场景额外在新进程执行 `--resume` 和 `--fork-session`，请求中未见合成受保护值。标签映射不跨进程恢复。
- 负对照：不加载插件，以及显式 `--safe-mode` 禁用插件时，原值确实进入请求与工具历史。证明录制器能够检出泄露，也证明插件缺席不是系统级失败关闭。

持久化断言仅覆盖这些实际宿主路径；不会据此宣称遥测、工具直接联网、所有原始缓存文件或第三方插件均无旁路。真实 compact 请求、桌面 UI 活跃会话、多实例组合与 worker 崩溃仍未做完整验收。

## 性能

测量原生 `$.tool.call` 完整往返，包含输入检查、原始结果检查、替换、复检及返回；mock 工具立即返回固定内容。规则预编译和宿主启动在计时外，模型网络与真实工具耗时也在计时外。输出为 10 KiB、100 KiB、1 MiB、4 MiB − 1 KiB，规则数 8/100/1000，并发 1/4；clean 与 redacted 共 48 组。大规则组增加未命中的 exact observe 规则，不能代表任意复杂规则组合。

每组预热 5 轮、测量 20 轮：并发 1 为 20 样本，并发 4 为 80 样本。Date.now 的毫秒精度以及样本量使 p99 只是这次样本的高分位，不能视作生产 SLO。空注册模块基线用于单独估计宿主调度/结果传输开销；Mods 测试框架要求一个模块，因此它不是完全没有 Mods worker 的真实进程。

下面是 8 条规则的结果，单位 ms；三列数值均为 p50 / p95 / p99：

| 输出大小 | 并发 | 空注册模块基线 | clean | IP 脱敏 |
| --- | ---: | --- | --- | --- |
| 10 KiB | 1 | 0 / 1 / 1 | 1 / 1 / 1 | 1 / 1 / 3 |
| 10 KiB | 4 | 1 / 1 / 1 | 2 / 3 / 3 | 3 / 3 / 5 |
| 100 KiB | 1 | 0 / 1 / 1 | 2 / 3 / 3 | 4 / 5 / 8 |
| 100 KiB | 4 | 1 / 1 / 1 | 9 / 9 / 13 | 15 / 16 / 16 |
| 1 MiB | 1 | 1 / 2 / 5 | 19 / 20 / 24 | 34 / 38 / 39 |
| 1 MiB | 4 | 2 / 4 / 4 | 79 / 81 / 83 | 139 / 140 / 143 |
| 4 MiB − 1 KiB | 1 | 2 / 3 / 4 | 76 / 79 / 80 | 扫描超时扣留 |
| 4 MiB − 1 KiB | 4 | 8 / 12 / 14 | 301 / 335 / 337 | 扫描超时扣留 |

48 组中 34 组完成完整采样，14 组触发 `inspection.timeout` 后停止采样，进入故障扣留；没有将后续便宜的锁定拒绝计为扫描延迟。超时组包括 1 MiB/1000 规则、接近 4 MiB/100+ 规则，以及接近 4 MiB 的所有脱敏组。完整记录含 warmupBlocked、blocked、执行次数及未完成标记。

并发往返延迟包含宿主排队，不等于单次检测器扫描持续时间，因此总延迟可超过 100 ms。实际宿主可能在 text/result 中重复表示内容，字节额度按受检表示计算；这个基准只放一份 stdout，大输出结果不能据此承诺普遍可用。

与原设计目标比较：单并发 100 KiB 脱敏 p95 达到 5 ms，1 MiB 脱敏 p95 38 ms **未达到** 20 ms 目标；大输出仍需进一步优化。没有放宽超时预算、提前释放扫描中的内容或隐藏扣留数据以满足性能目标。
