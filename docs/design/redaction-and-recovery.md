# 工具结果脱敏与拦截后恢复：设计及执行计划

状态：**方案已获批准，插件 0.2.0 / 桌面 0.3.0 已实现首批能力，现有用户规则未自动迁移。**

本文保留完整设计目标；本版具体实现、宿主能力导致的范围收窄见 [使用说明](../recovery-redaction.md)，已验证与未验证路径见 [验收记录](../recovery-redaction-acceptance.md)。

日期：2026-11-16。实现基线：插件 0.1.25；桌面报告 schema 2。

本文同时覆盖两项能力：可可靠处理的工具结果在本地脱敏后继续返回；必须拦截的结果停止当前轮次，允许用户随后提交安全指令继续原会话。实际运行行为以 README、使用说明和验收报告为准，不能将下文目标范围全部视为已实现。

## 1. 目标与推荐决策

### 1.1 用户可见行为

1. 读取普通诊断文本，命中可准确定位的 IP：返回带明确说明的脱敏结果，模型可以继续分析。
2. 命中必须阻断的规则，或无法可靠脱敏：扣留整份结果，停止当前轮次，说明下一步可做什么。
3. 用户随后发送“跳过这段日志，改为检查构建状态”：新消息检查通过、旧轮次完成隔离后，在原会话中继续。
4. 用户消息本身命中规则：只拒绝这条消息，允许修改后重发。
5. 检测器异常或初始化失败：显示故障状态；通过本地健康检查后才能恢复。

推荐默认：**可支持的 IP 结果脱敏；其余规则保留原动作；普通拦截后由下一条安全的用户消息恢复。** 这是目标默认，须按第 11 节分阶段启用，不能直接改写用户现有规则。

### 1.2 首批范围

| 能力 | 首批范围 | 后续范围 |
| --- | --- | --- |
| 脱敏入口 | 已验证适配器中的 `tool.result` 文本 | 更多明确结果格式 |
| 脱敏检测器 | IP：IPv4、IPv6、映射 IPv6、端口及 URL 中的地址 | 凭据、设备标识、主机名、精确值、域名 |
| 文本载体 | 普通诊断文本；已支持结构中的字符串值 | 更多 MCP、后台任务及跨工具转述路径 |
| 恢复 | 同一运行实例内，普通规则拦截后的新用户轮次 | 具备充分上下文证据的其他恢复路径 |
| 用户输入、工具参数 | 检查并拒绝；不自动修改 | 独立设计后再考虑 |
| 自动上下文 | 保留现有配置覆盖范围 | 单独验收后扩展 |

不承诺任意图片、PDF、编码或混淆内容脱敏，不把本功能描述为网络出口隐藏、已执行操作撤销或历史信息撤回。

### 1.3 本次 review 建议确认的产品选择

- 普通拦截采用“下一条安全的用户消息继续”，不要求每次输入解锁命令。
- IP 用完整代号替换，不保留地址前后几位；端口默认保留，便于诊断。
- 同一插件运行实例内，相同 IP 使用相同代号；跨重启不保存真实值映射。
- 首批仅支持 IP 脱敏，凭据等仍拦截整份结果。
- 明确的源码、补丁、可执行配置及不能判断用途的内容，脱敏能力不足时回退拦截。
- 新策略先显式试用，再调整新安装默认；已有用户配置不静默放宽。

## 2. 现状与需要改变的地方

| 当前实现 | 位置 | 本次变化 |
| --- | --- | --- |
| 单一 `blocked` 布尔值，一次命中后后续提示、工具、推理一直被拒绝 | `hooks/register.js` | 改为引擎健康状态、轮次状态、调用归属分别管理 |
| `scan()` 返回第一处阻断及规则/原因，没有全部位置 | `src/core.js` | 保留快速阻断接口，新增有界匹配收集与转换接口 |
| IP 解析丢弃原始文本偏移 | `src/core.js` 的地址提取 | 保存原始跨度与规范化地址之间的关系 |
| 字段规则共用值提取器，主要返回原因码 | `src/assignment-values.js` 等 | 首批不改语义；后续脱敏必须在共享提取器上扩展位置证据 |
| 规则仅有 `block` / `observe` | `schemas/rules.schema.json` | 新配置版本增加 `redact` 及恢复策略 |
| 桌面只归档插件实例第一次拦截 | `hooks/register.js`、`desktop/src/sessions.rs` | 支持同一实例多次暂停、恢复、脱敏计数 |
| 真实 CLI 回放主要是单次提示，使用 `--no-session-persistence` | `scripts/e2e.py` | 增加多轮、持久化、重启恢复和实际请求体检查 |

旧版设计中的“新轮开始不能自动清除阻断”是历史默认。本方案只允许**经过验证的新用户输入边界**触发受控恢复，不能在任意 `turn.start` 或 `session.start` 上无条件清锁。

本次本机排障验证了特定会话进程重启后状态恢复，以及那次被扣留结果在记录中只留下固定提示。这不等于所有保存、恢复、分叉或并发路径已经通过验收。

## 3. 统一动作与优先级

### 3.1 规则动作

| 动作 | 工具结果处理 | 会话行为 |
| --- | --- | --- |
| `observe` | 原样返回，只记录有界规则统计 | 继续；不提供该规则的内容保护 |
| `redact` | 全部命中可可靠替换并复检通过后，返回转换结果 | 继续本轮 |
| `block` | 整份结果扣留，返回固定安全提示 | 暂停当前轮，等待新用户指令 |

同一结果按以下顺序决定：

1. 扫描故障或不满足完整处理条件：扣留。
2. 原始结果中任何 `block` 规则命中：整份扣留。
3. 存在 `redact` 命中：完成全部替换及复检后才能返回。
4. 仅 `observe` 命中或无命中：按现有语义处理。

**先在原始内容上完成动作判定，再替换。** 不能先消除一个 IP，让覆盖同一值的自定义 `exact` 阻断规则失去检查机会。规则顺序不得改变这个结论。

### 3.2 按入口区分

| 来源 | 命中时 | 恢复方式 |
| --- | --- | --- |
| `user.prompt` | 拒绝这一条；不创建新的可执行轮次 | 用户修改并重新发送；已有暂停状态保持 |
| `tool.input` | 拒绝执行，暂停所属轮次；不改写命令或参数 | 下一条安全用户消息 |
| `tool.result`，可脱敏 | 返回转换结果和固定说明，保留工具成功/失败属性 | 继续本轮 |
| `tool.result`，必须拦截 | 扣留结果，停止所属轮次及其后续调度 | 下一条安全用户消息 |
| `prompt.context`，已启用且命中 | 抑制内容并暂停，不靠普通消息直接清除问题 | 修复或重新验证上下文；能力不足时要求干净会话 |
| 初始化、扫描或 hook 故障 | 扣留、暂停，显示固定故障类别 | 本地健康检查通过后，仍由安全用户消息开启新轮 |

`redact` 首批只能配置在 `tool.result` 的 IP 规则上，其他组合校验失败，不能静默当作放行。

## 4. 拦截后恢复状态机

### 4.1 分离状态

建议新增独立运行状态模块，避免所有逻辑继续堆在 hook 中。

- 引擎：`initializing / healthy / faulted / ended`。
- 用户轮次：`active / pausing / paused / closed`。
- 每轮持有不可变 `epoch`、宿主轮次 ID、父子代理归属、未结束调用计数和固定暂停原因。
- 每个工具调用在进入时捕获所属 `epoch`，返回时再次核对。
- 历史“发生过拦截”单独记录，不用于判断当前能否继续。

状态示意：

```text
初始化通过 → healthy + 等待用户输入
  用户消息通过 → active(epoch N)
    结果通过或脱敏成功 → 继续 epoch N
    必须扣留 → pausing → paused(epoch N)
      新用户消息通过 + 恢复条件成立 → active(epoch N+1)
    引擎/扫描故障 → faulted
      本地健康检查通过 → 等待用户输入；不重发旧结果
```

### 4.2 普通拦截的原子顺序

1. 在任何 `await` 之前，把所属轮次置为 `pausing`，撤销该轮新的工具、代理和推理调度资格。
2. 将本次结果转换成固定安全拒绝；不把原文挂到错误对象、通知或报告上。
3. 请求宿主停止该轮。停止请求失败时也不能释放结果；记录固定故障码。
4. 同轮尚未返回的调用全部按旧轮处理，其结果只能丢弃或转换成安全终止提示。
5. 确认宿主允许安全开始下一用户轮次后进入可恢复状态。

不能假定 `turn.abort` 会撤销工具副作用、取消所有子代理或等待所有并发回调完成。

### 4.3 下一条消息恢复的必要条件

同时满足以下条件才能创建新 `epoch`：

- 引擎健康，规则快照有效。
- 该输入确实来自宿主的用户提交路径；后台消息、工具结果、自动重试和模型生成内容不能自行触发恢复。
- 新消息通过原有输入检查，且不是对旧敏感结果的授权放行。
- 暂停原因属于可恢复的工具规则拦截，而非未解决的上下文污染或故障。
- 旧轮的下一次模型调度已经封闭，结果已替换为安全提示；宿主的历史/待发送队列中不存在待回灌的原始结果。
- 旧调用已经结束，或经实际接口验证能在整个生命周期内按旧 `epoch` 隔离。

最后一条采用两级实现：先实现“调用已结束才能恢复”的保守版本；只有测试证明隔离可靠，才允许旧调用仍在运行时开启新轮。等待超时不自动放行，显示“上一轮仍在结束，可稍后重试”。被拒绝或等待中的新消息不自动排队发送。

恢复后，旧 `epoch` 永远保持关闭。旧工具晚返回、旧代理发消息、旧回调抛异常，都不得重新激活旧轮或覆盖新轮的普通状态。确实属于引擎级故障的异常仍应使引擎进入故障态。

### 4.4 用户提交来源验证是发布门槛

当前 `prompt.submit` 是否能区分用户提交、自动注入、远程用户输入和后台消息，需要以本机 Mods 类型及实际事件验证。不得通过提示词文本、特殊口令或“看起来像用户消息”来判断身份。

若宿主没有可靠来源证据，自动恢复不能发布。回退方案是经过验证的本地用户命令或宿主恢复动作；若命令也能被模型伪造调用，则保留进程重启方案并明确限制。

### 4.5 故障恢复

区分固定原因：初始化失败、扫描超时、大小/深度/节点超限、转换失败、残留命中、未知结果结构、hook 异常。原因不含原值或异常原文。

- 普通已知超限结果永久扣留；新请求可选择更小范围，但不自动重试原命令。
- 扫描异常/超时后，通过本地合成探针和有效规则检查恢复引擎健康，不重新扫描或释放旧原文。
- 初始化失败须完成可信配置修复并重新初始化；新消息不能将故障状态直接清空。
- 上下文来源命中必须验证问题已经去除；不能仅通过探针宣布恢复。
- 不增加“忽略所有错误继续”或“原样放行一次”的恢复入口。

## 5. 脱敏处理流水线

```text
工具返回暂存
  → 验证结果结构、累计资源预算
  → 扫描原始内容，收集全部动作及精确位置
  → 存在 block / 无法处理：扣留并暂停
  → 检查结果是否适合转换
  → 合并重叠位置，生成脱敏副本
  → 加入固定脱敏说明
  → 用同一规则快照复检最终可见内容
  → 核对 epoch 仍有效
  → 返回脱敏结果
```

每一步均成功才能发布。禁止边扫描边把片段交给模型；失败时销毁未发布副本并返回固定拒绝。

### 5.1 内部接口草案

保留 `compile().scan()` 给现有快速阻断调用及兼容测试。另增概念接口，最终签名以实现阶段类型设计为准：

```ts
type Decision =
  | { kind: 'pass'; observed: string[] }
  | { kind: 'redacted'; value: unknown; summary: SafeSummary }
  | { kind: 'withhold'; reason: SafeReason; ruleIds: string[] }
  | { kind: 'failure'; reason: SafeFailureReason };

// context 含来源、工具、规则快照、预算及当前运行实例的代号分配器。
inspectAndTransform(value: unknown, context: InspectionContext): Decision;
```

匹配对象只在本地内存中流转，含规则、类别、结构路径、原始跨度及转换所需证据。原值、结构路径和文本偏移都不进入错误提示或桌面报告，因为路径的键也可能敏感。

### 5.2 精确位置与规范化

- IP 检测复用当前解析、CIDR 豁免、国家分类和边界规则，不创建语义不同的“脱敏专用正则”。
- 保存 `[start, end)` 原始跨度；明确 JavaScript UTF-16 偏移与 UTF-8 字节预算的区别。
- ANSI、Unicode 转义等规范化必须保留源位置映射。无法可靠映射时，选择已验证的整字段替换，或扣留；不能猜测跨度。
- IPv6 的括号、zone、映射 IPv4 必须整体处理，避免留下 zone 设备线索或部分地址。
- 同一文本内多个命中、相邻命中、重叠规则和重复值必须全部处理；替换按原始偏移倒序或单次构造进行。
- 普通 JSON 的字符串值可替换；对象键命中、键重名风险、非字符串类型必须改型时，首批扣留。
- JSON 字符串可在明确深度预算内解码、处理并重新编码。检测到重复键或无法无损解释的形式，不用 `JSON.parse()` 丢字段后宣称完整处理，回退扣留。
- 部分 JSON、截断工具输出和无法识别的编码不因“已经处理可见部分”而获得完整保护声明。

### 5.3 代号与信息保留

示例均为虚构内容。测试可显式配置文档地址网段命中，不依赖默认国家库对示例地址的分类。

```text
输入：local=srflx 203.0.113.17:54321 remote=srflx 203.0.113.17:62000
输出：local=srflx [IP_1]:54321 remote=srflx [IP_1]:62000
```

- 不输出地址前缀、尾数、原始地址哈希或可逆编码。
- 相同规范地址在同一插件实例内复用代号；IPv4 与映射 IPv6 是否统一按同一地址处理，采用现有地址分类语义并覆盖测试。
- 代号仅为诊断关系标记，不是可连接地址，不提供模型可调用的反向解析接口。
- 映射只存本地有界内存，禁止落盘、写日志或发送。可采用实例随机密钥的带密钥摘要作为查找键；需先确认运行时能力和开销，不能用可枚举 IP 的普通哈希替代。
- 映射容量首版建议上限 4096 个地址，作为待测参数；满额时扣留当前结果并提示固定容量原因，不复用旧编号、不回退原文。后续若需要无关联代号模式，单独设计并验收。
- 进程重启后重新分配，标明代号属于新的运行实例；不保证跨重启、分叉会话的同号同值。普通暂停恢复保留当前实例映射。
- 端口默认保留，IP family、重复关系和出现次数仍可能透露网络结构；这是所选择的信息保留边界，不称完全匿名化。后续若用户要求保护端口，应单独配置。

### 5.4 结果语义与适配器

- 保留 `isError`、退出码及宿主要求的结果字段；原命令失败不能因脱敏被改成成功。
- 不任意向结构化对象增加字段；说明通过宿主支持的文本内容块或已确认的文本包装加入，并对最终包装一并复检。
- 固定说明示例：`[Agent Safeguard] 本结果包含已替换的敏感字段；代号不是真实地址，不可用于连接或配置。`
- `stdout`、`stderr`、错误消息、嵌套可见字符串均覆盖；不能只改正常输出而遗漏错误输出。
- 明确的代码、补丁、执行配置和未知内容，首批不得承诺“语义不变”。变更会导致数据无法正确解释时扣留。
- 不能仅根据工具名、项目名、文件扩展名或函数名放行。Bash 输出可能是日志，也可能是源码，必须为可转换结果定义保守的结构/内容资格；不确定时扣留。
- 第一阶段先验证 Bash 文本结果；MCP 必须单独验证文本块、结构化内容和错误路径，未验证的形态保持扣留策略。
- 在宿主支持的边界内阻止明显的带脱敏代号工具参数被当成地址执行，并返回“需本地处理真实值”的固定提示；这不能替代模型行为约束，也不能阻止所有间接复制或改写。

### 5.5 复检与冲突

复检使用原始规则快照，覆盖所有仍生效的阻断和脱敏规则及最终说明。还有需要保护的命中就扣留，不循环无限重写。

不将 `[IP_1]` 等文本添加为全局白名单；原始内容伪造同样标记不能跳过扫描。自定义精确规则碰巧命中代号或说明时仍优先阻断。

复检与第一次扫描共享检测器，因此共同漏检仍可能存在。测试还须独立检查合成原值是否出现在最终请求体，不能仅凭 `scan(redacted).blocked === false` 判定安全。

## 6. 并发、持久化与真实请求边界

### 6.1 并发

- 每个回调持有固定轮次归属；禁止在结果返回时才读取当前全局轮次并认领。
- 子代理绑定父用户轮次；暂停父轮后，旧子代理不能通过发起新内部轮次恢复执行。
- 旧轮关闭后，成功扫描、脱敏完成或异常回调都必须经过最终轮次门禁。
- 并发多个普通脱敏结果可以逐个在完整检查后返回；若同批另一结果触发阻断，尚未发布的结果也扣留。
- 已经安全返回的结果无法“撤回”；已在途模型请求和工具副作用也不能由状态机倒退消除。
- 自动重试、后台完成事件、压缩和 agent.spawn 使用相同轮次门禁，不允许绕过恢复条件。

### 6.2 历史与恢复

必须验证以下位置保存或消费的是安全结果：宿主工具消息、会话 JSONL、UI 展示、后续模型请求、摘要/压缩、重启 resume、分叉及可支持的后台结果。

若宿主在插件拿到结果前就保存原文或发送流式内容，结果转换不能消除这条旁路。该路径不得列为已保护；必要时禁用其脱敏继续能力并保留扣留，若扣留也不足则明确不支持。

只有“新进程 `blocked=false`”不能证明恢复安全。新版本恢复逻辑需识别自身受保护的记录边界；对来源未知或旧版历史不宣称全量重验。无法取得安全上下文证据时，引导建立干净会话，不自动搬运原始历史。

本阶段不存储被扣留原文用于稍后“重新批准”，不创建可被模型访问的隔离原文文件。

## 7. 配置、升级与回滚

### 7.1 新配置版本

采用规则 schema 2，运行时同时读取 schema 1 和 2。旧 schema 1 规范化为当前行为，保留原有会话锁定语义；用户显式迁移后采用新恢复策略。避免旧引擎误读新动作而放行。

建议新策略字段（最终字段名在实现前固定）：

```json
{
  "schemaVersion": 2,
  "policy": {
    "onMatch": "withhold-and-stop-turn",
    "onInspectionFailure": "block",
    "onUnsupportedContent": "allow",
    "recovery": "next-safe-user-prompt"
  }
}
```

这是策略片段，不是完整可 apply 配置。`recovery` 另允许 `manual` 和 `session-lock`；`manual` 仅在可靠用户命令入口通过验收后开放。

### 7.2 按来源拆规则

现有 `network.address` 同时覆盖用户消息和工具结果，不能直接把整个规则改成 `redact`。迁移需拆为：

- `network.address.output`：保留原检测器参数、CIDR 豁免与工具范围；`sources: ["tool.result"]`，`action: "redact"`。
- `network.address.input`：保留其他原来源及限制，`action: "block"`。

迁移只作用于用户明确选择的规则，保留自定义规则、启用状态、源范围及未知地区策略；旧 ID 到新 ID 的说明用于桌面展示和审计，不丢弃历史。

`onUnsupportedContent` 保留现有用户值；`allow` 表示未支持二进制未受检查，不能展示成“脱敏成功”。同一结果的可见文本仍检查。

### 7.3 升级顺序

1. 发布可读取新旧报告及规则格式的桌面/管理端。
2. 安装支持新格式但仍使用旧配置的插件。
3. 提供规则迁移预览、校验和备份；显式应用新策略。
4. 在新实例加载，或经另行验证的安全轮次边界切换；本阶段不新增一般性规则热加载。

回滚必须先恢复兼容旧引擎的配置，再启动旧插件。安装器检查版本不匹配并明确失败，不依赖“旧版崩溃应该会挡住”保障安全。用户真实规则与备份只保存在私有本地目录。

## 8. 状态与桌面展示

建议新增报告 schema 3，新桌面兼容读取 1/2/3；旧桌面严格拒绝未知字段，不能直接给 schema 2 偷加字段。

新的安全状态信息至少包括：

- 引擎健康、当前是否可接收用户输入、暂停原因及恢复方式。
- 最近动作：通过、脱敏、扣留、拒绝输入、故障。
- 本实例的脱敏结果数、替换次数、暂停次数、恢复次数。
- 规则版本、插件版本、运行实例标记、支持范围。

当前 `blocked` 在兼容状态命令中可保留，但语义明确为“当前是否禁止继续”，不表示“历史是否曾命中”。`lastRule` 等历史原因和当前状态分别展示。

同一实例可以多次拦截，不能继续只写第一次事件。使用独立事件序号及幂等 ID，异步合并写入，保留有界历史和清理策略。写入失败不改变扫描决定，不承诺完整持久审计。

文案应区分：

- “结果已脱敏，任务继续。”
- “本轮已暂停，敏感结果已扣留。可发送新的指令。”
- “上一轮仍在结束，请稍后重试。”
- “防护检查出现故障，需恢复检查能力后继续。”

报告、原因、提示均不包含命中原文、可逆映射或原始异常。自定义规则显示名/ID也需要有界和隐私处理，不能假定用户定义的名称一定无敏感内容。

## 9. 验证计划与发布门槛

### 9.1 检测与转换单元测试

- IP：IPv4、压缩 IPv6、映射 IPv6、URL、括号、zone、句尾标点、相邻地址、重复地址、边界反例。
- 规则：国家/CIDR/any、现有豁免、未知地址；原文中 `block` 与 `redact` 重叠及规则乱序。
- 转换：Unicode 偏移、ANSI、JSON 转义、两层嵌套、数组、重复 JSON 键、敏感对象键、源数据不可变。
- 全量：开头/中间/末尾命中、多个字段、stdout 与 stderr 同时命中、脱敏输出再次命中其他规则。
- 失败：位置映射失败、转换抛错、各类超限、代号容量用尽、未知形态、伪造脱敏标记。
- 无命中正常结果保持原样；失败结果保持失败语义；自定义规则不被脱敏掩盖。

若后续修改共享值提取器，凭据、设备标识和主机名必须共同执行跨语言表达式矩阵，并覆盖相邻字面量、结构化数据、独立格式和模拟器局部例外。

### 9.2 状态机与原生 Mods 测试

- 敏感用户消息拒绝后，安全消息可以继续；不重发被拒绝文本。
- 普通工具拦截停止本轮；下一条安全消息恢复；仍敏感的下一条不恢复。
- 迟到 `session.start`、内部 `turn.start`、后台通知不能清锁。
- 两个用户提交竞争、恢复期间再次拦截、重复恢复命令不会创建重叠活动轮次。
- 慢工具在新轮开始后返回、旧回调异常、父子代理并发、扫描结束与暂停交错均不能泄露旧结果。
- 暂停时未结束调用数量正确；abort 失败或等待超时不能误报已恢复。
- 引擎故障不能被普通消息重置；健康探针通过也不会释放旧结果。
- 多次拦截/恢复事件唯一，报告失败不阻塞判定，报告不含原文。

### 9.3 真实请求路径测试

使用隔离 HOME、虚构凭据、本机模型桩和合成结果；不继承真实账号或会话历史。

新增回放的工具调用只引用本地预置的合成文件或固定生成程序，不把敏感测试值直接写进模型生成的工具参数，也不通过 base64 参数把它预先交给模型。否则无法区分“测试输入已经携带原值”和“工具结果泄露”。保留现有回放用于兼容回归，新的隐私验收使用独立夹具来源。

| 用例 | 必须观察到的结果 |
| --- | --- |
| 无防护对照 | 合成敏感值确实能进入请求，证明记录器有效 |
| 脱敏成功 | 原轮有后续请求；请求中只有安全代号和说明，无受保护原值 |
| 原命令失败后脱敏 | 后续请求保留工具失败信息，原错误中的受保护原值消失 |
| 必须拦截 | 本轮没有消费原结果的后续模型请求；历史仅有安全提示 |
| 拦截后新用户消息 | 原会话能新增请求；新的请求及历史不含旧被扣留原文 |
| 并发与迟到结果 | 恢复前后所有请求中均不存在旧原文；旧轮不能继续调度 |
| 保存、重启、resume、分叉、compact | 实际请求及摘要只包含脱敏结果或固定拒绝，不重新引入原文 |
| 超时、未知格式、转换失败 | 不返回半成品，也不返回原文；故障与普通命中可区分 |
| 插件禁用、缺席、worker 崩溃 | 如实记录宿主行为，不冒充插件可控制的失败关闭 |

记录器检查所有模型可见字段及可识别的转义/编码形式，不只查一个 `user` 字段。流式工具内容、缓存引用、附件或宿主旁路若无法观测，必须单列未覆盖范围。

CLI 与桌面内嵌引擎分别验证版本和结果；实际 MCP 与后台子代理未完成测试时，不能用 Bash 模拟结果替代覆盖声明。

### 9.4 性能与资源

沿用当前 4 MiB 文本、深度/节点和 100 ms 协作预算的基线语义；第一次扫描、转换、复检共享总处理预算，不是每阶段重新获得 100 ms。统计解码和转换扩张，超过处理/输出预算整份扣留。

测量完整 `tool.call` 路径以及分阶段耗时：10 KiB、100 KiB、1 MiB、上限附近；无命中/稀疏/密集命中；7/100/1000 条规则；并发 1/4。报告 p50/p95/p99、字节数、匹配数、规则数、并发数、峰值内存估计和超时比例。

现有实现作为同机基线；建议无命中路径中位耗时退化不超过 10% 作为评估目标，绝非实测结论。若预算内无法完成，优化、缩小支持范围或回退扣留，不能提前释放或为通过测试随意放大预算。

## 11. 试用、发布与完成定义

1. Review 本文的默认行为、信息保留边界和首批范围。
2. P0 使用纯合成数据完成接口验证；所有真实路径结论附版本。
3. P1 先完成恢复能力，不以输入任意消息清零布尔值代替状态机。
4. P2/P3 在隔离配置中启用 IP 脱敏；通过实际请求和历史检查后进入试用。
5. P4 提供明确迁移预览，真实规则保留备份；更新只影响新加载实例。
6. 验收通过后，新增安装可推荐新策略；旧用户按选择迁移，保留会话锁定模式。

完成须同时满足：

- 原会话普通拦截后可接收安全新消息，旧轮结果不能进入新轮。
- 已支持 IP 结果可继续分析，受保护原值不出现在已验收的请求及历史路径。
- 工具失败语义、原有阻断规则、CIDR 豁免、共享提取逻辑均无未说明退化。
- 不支持/异常/超限分别有明确行为，插件缺席与宿主故障的边界如实展示。
- 多次暂停、恢复、脱敏在状态页可解释；观测不含原文、不阻塞检测。
- 配置迁移、版本降级、安装更新及新会话加载完成验证。
- 全部安全门槛有合成测试证据，性能数据是实测而非目标。

本计划获批只进入实现阶段；不将本文中的接口草案、目标或测试清单描述成已具备的产品能力。
