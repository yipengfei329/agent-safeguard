# Agent Safeguard 桌面一期功能与页面设计

状态：已进入实现，2026-11-14；落地范围与剩余门槛见 `docs/desktop-v1-acceptance.md`。基于 Rust + GPUI Kit 原型，范围为个人用户、本机 Claude Code、用户级插件安装。目标是让用户无需命令行即可完成安装、确认会话接入、理解阻断原因和修改基础规则。

这是桌面产品的一期，不替代检测器历史目标规格 `docs/v1-design.md`，也不表示状态通道、在线更新或三平台发布已经实现。当前能力与测量以 `docs/desktop-prototype.md` 为准。

## 1. 最小可用范围

一期只有三个主页面：**概览、工具、规则**。帮助、关于和本地数据说明放在侧栏底部的小入口；不另建设置中心、统计看板或通知中心。

| 必须交付 P0 | 一期明确不做 |
| --- | --- |
| Claude Code 环境识别、手动定位、用户级安装、更新、禁用/启用、卸载 | Codex/Gemini 防护适配、其他工具占位卡、插件市场 |
| 会话自动上报最少必要状态、区分当前状态与旧记录 | 用户手动复制 JSON 作为正常使用流程、全局“系统已保护”开关 |
| 最近阻断/异常记录及处理指引 | 全量操作审计、图表、扫描内容预览、正文检索、云端上传 |
| 内置规则开关、自定义精确文本、保存与上一版恢复 | 任意正则、规则脚本、逐工具策略编辑、云同步、导入他人策略 |
| 无需用户安装 Git/npm/Rust/Node 的普通用户流程 | 账号登录、开机服务、系统托盘常驻、自定义主题 |
| Mac/Linux/Windows 各自的构建和安装验收 | WSL、远程主机、云端会话、普通 Claude Chat/Cowork |

保留现有 JavaScript 检测引擎。桌面负责管理和显示，既不是模型请求代理，也不是检测器的必经依赖。

## 2. 导航与首次使用

- 默认进入概览，左侧固定三项导航；工具页名称采用“工具”，不把 harness 或 Mods 作为用户必须理解的术语。
- 新用户的概览只显示“连接 Claude Code”、一句用途和一个主按钮“安装插件”；点击进入工具页的就地安装流程。
- 已安装用户的概览展示会话状态、待处理事项和最近记录。无需再次进入安装向导。
- 工具页自动做一次只读检测，手动“重新检测”可重试。未知/未发现时允许“选择程序”，避免将 PATH 发现失败等同于未安装。
- 不要求用户在三个页面之间反复往返。安装完成、阻断详情和规则保存均提供一个明确的下一步。

### 首次使用主流程

下载对应平台应用 → 发现 Claude Code → 点击“安装插件” → 安装完成但显示“等待新会话” → 用户在 Claude 中新建会话 → 收到该会话的有效状态 → 概览显示“已连接 1 个会话”。

“安装成功”仅指文件部署与宿主注册完成。“会话已连接”仅指状态通道有证据，不代表所有历史内容、所有宿主入口或所有进程都被保护。

## 3. 概览页

回答三个问题：**是否有会话接入；是否有需要处理的问题；下一步做什么。**

### 布局

1. 页标题“概览”，右侧为“刷新状态”和最近刷新时间。
2. 一个主状态区域：图标、状态名称、一句原因、一个主动作。不存在“安全评分”“今日保护次数”等指标。
3. 会话列表：本地短编号、状态、插件/规则版本、最近更新时间。编号由本地生成，不显示项目路径、机器名、账号或提示词。多会话并列呈现，不让一个正常会话掩盖另一个异常。
4. 最近记录：时间、会话编号、类别、处理结果、详情入口。仅包含阻断、检测异常、初始化失败和版本切换等必要元数据；不记录正常工具输出。
5. 页面底部短提示“仅显示本机接入会话”，覆盖说明按需展开。

### 主状态与动作

| 证据/状态 | 主文案 | 主动作 |
| --- | --- | --- |
| 未发现 Claude 程序 | 尚未找到 Claude Code | 选择程序；次级入口为安装说明 |
| 程序存在、插件未安装 | 安装插件后开始使用 | 安装插件 |
| 插件已安装，未收到新会话证据 | 插件已安装，等待会话 | 查看连接步骤 |
| 插件配置被禁用 | 插件已禁用 | 启用插件 |
| 一个或多个新鲜状态报告 | 已连接 N 个会话 | 查看会话；存在异常时主动作改为查看原因 |
| 某会话发生规则命中并锁定 | 1 个会话需要处理 | 查看阻断详情 |
| 扫描超时/内部错误/不支持内容 | 1 个会话检查异常 | 查看原因；不使用“发现敏感信息”文案 |
| 最后报告过期，无法确认仍在线 | 会话状态待确认 | 刷新状态；旧记录保留时间标记 |
| 明确收到会话结束 | 当前没有活动会话 | 查看连接步骤 |
| 管理端读取状态失败 | 暂时无法读取状态 | 重试；不据此宣称宿主停止或结果已放行 |

聚合顺序：未安装/禁用等配置问题与会话状态分栏显示；会话区优先显示已知阻断和检测异常，其次过期/未知，再显示已连接。旧会话仍可能持有旧插件，配置禁用不被描述为已经中止所有运行中的会话。

### 阻断详情面板

仅展示时间、会话编号、规则名称/编号、来源类型、动作、插件与规则版本。规则显示名可能由用户填写，仅留在本机，禁止导出原始内容或命中值；界面中不提供完整输出或截取片段。

动作分别表述：

- 工具参数命中：“已拒绝这次工具调用”。
- 工具结果命中：“已扣留工具结果，并阻止该会话的后续推理”；注明已执行命令的副作用没有撤销。
- 用户输入命中：“这次输入未提交”。
- 无法检查：“因检查异常未放行”，展示超时、内部错误、不支持内容的独立类别；若宿主动作无法确认则显示“处理结果未知”。

处理路径：查看对应规则 → 在本机修正输入/输出或编辑规则 → 新建会话继续。面板不提供“放行一次”“解除锁定”“重试原始输出”。编辑规则不解锁已阻断会话。

## 4. 工具页

一期只展示 Claude Code，不展示不能安装防护适配器的其他工具。后续通过适配器扩展，而不是预留一排不可用卡片。

### 页面字段

- 程序：已发现/未发现/版本不在已验证范围/检测失败，版本和“更换程序”入口。
- 插件：未安装/已安装/已禁用，当前版本、可用版本、用户级范围。
- 生效：新会话可加载；已有会话版本另在概览展示。
- 主按钮随状态变化：安装插件 / 启用插件 / 更新插件；没有待办时仅显示“检查更新”。
- 次级“更多”菜单：禁用、卸载。卸载默认保留用户规则，清除规则作为单独明确的选择，不连带删除其他插件和宿主配置。

### 安装与更新流程

1. 检查兼容性，验证目标程序和安装范围。未知版本不宣称已兼容。
2. 准备内置插件或来自固定可信发布源的更新包。
3. 校验版本和真实性后，暂存并调用宿主正式安装/更新命令。
4. 重新查询宿主注册信息，显示“安装完成/更新完成，等待新会话”。
5. 等到新会话上报匹配版本，才将该会话版本标记为已生效。

以文字步骤呈现进度：“检查环境 → 安装插件 → 确认安装”；没有真实进度时不伪造百分比。操作期间禁止冲突按钮。安装/更新失败保持已验证旧版可用，说明恢复的是哪些源文件；宿主配置若不能确定恢复则引导重新检测，不能笼统提示“已全部回滚”。

插件在线更新在一期内保留**手动检查和手动更新**，断网仍可使用现有插件。离线包可安装内置版本。桌面应用自身一期通过下载替换完整签名包升级，不再实现第二套后台自动更新服务。

覆盖说明折叠展示：仅经验证的本机 Code 会话；普通 Chat、Cowork、远程会话、自动上下文和附件等未验证能力不得宣称覆盖。桌面 Code 的 UI 内实际验收未完成前，不宣传全桌面支持。

## 5. 规则页

以表单管理规则，默认不出现 JSON。全页使用草稿模式：开关和表单只修改草稿，“保存更改”才提交，避免每次点击都改变配置。

### 页面分区

- 顶部：已保存版本、未保存更改数、查看会话版本入口。
- 内置规则四行：凭据、设备标识、主机名字段、IP 地址。显示简短说明、开关和作用范围。IP 文案为“检查未豁免的地址，默认排除本机及常见内网等网段”，不把它简写成只拦公网。
- 自定义敏感文本：名称、条目数量、启用状态、编辑/删除。默认不展示敏感值。
- 若已有更复杂配置：显示“其他已有规则 N 条”及只读类别/范围。保留原字段、检测器、规则 ID 与动作，不用基础表单重建整份配置，也不静默把 observe 改成 block。
- 草稿操作区：放弃更改、保存更改；“恢复上一版”置于次级入口，操作前显示变化摘要。

### 新增/编辑精确文本

字段：本地显示名称、敏感文本（一期每条规则一个精确值）、启用开关。默认区分大小写，明确说明“逐字匹配”；一期不开放正则或脚本。名称为空、值为空/超限时就地报错；错误中不回显被拒绝的内容。

规则 ID 由程序生成，显示名称存在管理端元数据中，不修改现有引擎 Schema。规则列表默认遮蔽值，只有明确编辑时可在本机查看，不自动复制或上传。新增规则默认 action=block，按已有适配器已验证的用户输入/工具输入/工具结果来源设置；不擅自添加自动上下文来源。

如果发现历史 exact 规则包含多个值或不同作用范围，则只读保留，不用单值编辑器覆盖。

### 保存、生效与恢复

- 保存前由与现有检测器一致的校验器完成结构和语义校验，涉及新增值时可用虚构样本做本地回归。
- 保存界面展示覆盖变化，尤其标明关闭/删除哪些规则；无需额外堆叠确认窗口。“保存更改”就是最后的明确提交操作。
- 校验失败保留草稿，旧配置和上一版不受影响；写入失败同样不报成功。
- 成功：新版本原子保存，保留上一版。提示“已保存，新会话生效”。活动会话仍显示实际加载版本；不自动把它们变为新版。
- 发现外部编辑或另一进程已保存时，拒绝覆盖并提示重新读取；用文件内容摘要和进程间锁解决竞争，版本号不作为唯一一致性依据。
- 恢复上一版也先校验、保存并注明新会话生效。没有上一版时禁用入口并说明原因。
- 修改后切换页面可保留会话内草稿；退出应用时提醒有未保存修改。未保存的敏感值不写普通日志或状态通道。

默认规则模板面向真实用户，不把测试用设备、域名、网段样例当作默认防护规则。虚构规则留在测试和演示模式。

## 6. 状态通道与体验约束

自动状态是概览的发布前置能力。原型的“手动粘贴 JSON”只保留为诊断备选，不作为正常用户步骤。此节为待验证接口要求，不宣称本机 Mods 已提供所需文件或调度接口。

- 插件上报随机本地会话标识、插件/规则版本、就绪/阻断/结束状态、安全原因类别、递增序号和时间；不带原文、路径、账号、IP、命中值或其可枚举哈希。
- 主会话/子代理关联只能基于已验证宿主接口；无法确认的范围明确标注未知，不自动计入已连接数。
- 提议健康报告周期 15 秒、45 秒未收到转为“状态待确认”。这是设计参数，不是实测保证；宿主挂起、机器休眠和恢复时必须能正确过期。
- 最近记录只保留本地最近 100 条元数据与最近会话状态，提供清除入口；列表不宣称完整审计。达到上限丢弃最旧显示记录，不影响检测判定。
- 报告异步、有界、可合并；扫描路径不做同步磁盘写入、不访问网络、不等待 UI 确认。状态通道失败不能改变原来拒绝/扣留行为，也不能直接等同于宿主失败关闭。
- 桌面退出后，插件检测独立继续。重新打开只能把仍有效且来源可核对的报告视为新鲜状态；旧文件不是插件仍在线的证据。
- 采集层必须验证本机 Mods 类型声明和真实路径。若状态能力不能满足上述约束，先保留“未知”和最后记录，不以模拟数据填入真实页面，也不发布实时状态承诺。

## 7. 交互与视觉规则

- 按最新反馈采用 Linear 风格：深色窄侧栏、紧凑图标导航、细分隔线与列表布局；灰阶组织信息，紫色强调主要操作，不引入大图或常驻动画。
- 默认窗口约 1040×740，最小可用宽度 800；窗口缩小时纵向滚动，详情面板改为整页，不压缩文本至难读。
- 概览显示运行状态，工具显示安装配置，规则显示期望配置，三者不混用一种“已开启”状态。
- 成功用短文本反馈；错误用具体类别加下一步。颜色辅助表达状态，不能只靠红绿区分。
- 所有按钮、开关、输入框支持键盘焦点与可访问名称。中文 IME、多屏缩放、系统浅/深色和关闭窗口行为分别验收。
- “关于”显示应用版本、插件版本、许可与数据位置；不在主要流程展示 Rust、GPUI、JSON、进程模型等实现信息。

## 8. 发布门槛与实施顺序

| 顺序 | 交付 | 验收标准 |
| --- | --- | --- |
| 1 | 安装闭环与三平台基础 | 从安装包启动；无需 Git/npm/Rust；发现/手动定位程序；安装/升级可复查；不改坏其他插件配置 |
| 2 | 自动状态最小通道 | 两个并行会话正确区分；命中、异常、禁用、未加载、结束、过期不混淆；UI 退出不改变检测行为 |
| 3 | 规则表单与校验 | 不要求普通用户自行安装 Node；原校验语义通过一致性测试；无效规则不覆盖旧版；未知规则无损保留 |
| 4 | 打包、恢复、性能 | 三平台安装/卸载、离线使用、更新失败、配置并发、睡眠恢复通过；完整路径复测而非只测 UI |

开发环境可继续使用 Node；正式用户包需要选定并验证自包含的校验执行方式。小型 JS 运行时兼容性和总包体须实测后定，不在此方案里承诺无成本移植或特定体积。

性能回归以当前原型的 7.68 MiB DMG、20.90 MiB app、启动 p50 375 ms / p95 449 ms、页面空闲 RSS 113–115 MiB 为本机基线。加入状态采集和校验执行后按相同方法重测，另测完整拦截路径 p50/p95/p99、输出大小、规则数和并发数；不提前把新版本表现写成既成结果。

### 一期完成的判断

新用户从应用中完成安装，创建 Claude 会话后自动看到该会话接入；遇到阻断能理解原因及下一步；通过表单保存一条自定义规则，并在新会话中确认加载对应版本。整个正常流程不需要复制状态 JSON、编辑配置文件或安装开发工具链。
