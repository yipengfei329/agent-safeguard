# 错误码字段误报（插件 0.2.5 / 桌面 0.3.5）

## 原因与修复

虚构代码 `errMissingPassword = "account-password-required"` 原先触发 `security.credentials / literal-value`。字段分类只看末尾的 `Password`，值判断又把带分隔符的错误码视作密码材料。Write 输入因此在执行前被拒绝；这不是输出被扣留，也不是上版模板修复失效，而是另一个未覆盖的字段语义。

共享提取器现在携带可选的字段证据。凭据策略只将分词后以 `err` 或 `error` 开头的字段标记为诊断候选；值仍经过同一提取器和凭据判断。只有完整值是有界、统一大小写的分隔词组，同时含对应凭据角色及错误状态词时，才识别为诊断标签。没有按项目、文件名、函数名或整段代码放行。

不透明值、数字和符号混合密码、插值模板及字面量拼接不享受这项标签识别。独立凭据格式、自定义精确规则及相邻字段继续检查。相同字符串若出现在普通 `password` 字段，仍按密码处理。诊断标签不是密码无效性的证明；用户需要保护某个标签形态的实际值时，精确规则仍有优先效力。

负结果缓存以字段角色和证据类型共同分区，避免先遇到错误标签后，把同样文本的普通密码字段也判为安全。设备与主机名策略不使用诊断标签证据。源位置继续只显示固定字段类别和扫描文本坐标，不保存原始字段名或值。

拒绝提示也去掉了“等待工作结束后提交安全消息”之后重复的“再提交安全消息”；需要健康检查时仍显示该步骤。恢复授权机制未改变，不自动重放这次被拒绝的 Write。

## 验证范围

所有公开样本均为虚构值。核心测试覆盖 Go 常量组、JavaScript、TypeScript、Swift、Rust、Python、Kotlin、Java、C++、grep、结构化对象和 JSON，以及普通密码、相邻凭据/设备/主机名、缓存隔离、拼接、独立格式、自定义规则。

真实 Claude 请求脚本新增五个场景：错误常量 Write 成功且文件内容一致；错误字段中的不透明凭据 Write 未执行；相邻普通密码 Write 未执行；诊断标签工具结果正常返回；错误字段中的本地虚构凭据结果被扣留且未进入后续模型请求或工具历史。每项都检查同进程后续安全消息恢复。模型生成的 Write 输入本来已为模型所知，输入拒绝不代表模型从未见过它。

私人失败请求只在被 Git 忽略的 `local/` 中复现，没有加入样本、报告或代码。完整私有写入内容使用修复后的扫描器通过，实际宿主路径则使用上述合成用例验证。
