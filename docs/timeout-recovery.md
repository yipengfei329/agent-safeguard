# 输入检查超时与会话恢复修复（0.2.1）

## 已确认的缺陷

0.2.0 的普通敏感信息拦截恢复通过了验收，但没有覆盖真实宿主的 Write 输入扫描超时。一次大段源码写入触发 `inspection.timeout` 后，会话进入 `faulted`；普通安全消息不能清除该状态。

拒绝分支还先调用 `turn.abort`，随后才返回 `deny`。宿主先结束正在分发工具的轮次，导致实际拒绝被通用占位文字替代：`Tool call did not complete … Nothing refused it`。因此用户既看不到检查超时的原因，也无法按原提示继续。

这是插件处理故障和宿主轮次生命周期的缺陷，不是 Swift 编译错误。事后本地重扫正常不代表原检查没有超时；目前没有足够证据确定那一次延迟的底层原因。机器负载和完整拦截路径的时间预算仍需单独评估。

## 修复后的行为

- 工具输入拒绝先返回明确原因和 `Tool not executed`；结果拒绝明确显示 `Tool ran; its result was withheld`。后续 `turn.step` 门禁阻止继续模型请求，不再提前 abort 当前分发。
- 仅工具检查的 `inspection.timeout` 可以在下一条可信消息边界自动重检。入口必须是宿主标记的 composer、bridge 或 sdk，不能是 meta、命令、后台通知或插件注入。
- 旧轮次、工具调用和子代理必须全部结束；上下文污染门禁仍然有效。新消息本身先完整扫描，再使用当前已编译规则快照扫描固定本地健康探针。两者都通过才创建新恢复轮次。
- 原被拒绝操作和被扣留结果不会重放；旧调用身份不能获得新轮次授权。不加载被修改的磁盘配置来自动解锁，也不放宽 100 ms 扫描预算。
- 自检失败、内部异常或资源超限继续保持故障，提示用户执行本地 `/agent-safeguard-check`。该命令成功后仍需新安全消息；上下文故障需要修复上下文来源并重启插件实例。
- schema 1 和 `session-lock` 保留原有锁定策略。拒绝信息仅包含固定说明和允许列出的原因代码，不包含原始敏感内容。

对已经加载 0.2.0 的实例，可先运行 `/agent-safeguard-check` 临时恢复条件，再发送安全的新消息。更新磁盘插件不会自动替换旧实例；需要在宿主支持时重新加载插件，或恢复到新实例。

## 验证方法与结果

测试只使用合成 Swift、虚构敏感标记、临时规则和回环地址的本地模型桩。未将用户项目源码、规则、日志、会话标识或实际地址纳入样本。

`npm run test:write-recovery` 在真实 Claude Code 2.1.325 宿主中运行 7 个场景，检查模型请求次数、工具是否执行、落盘历史、后续消息及状态。输入是 62,995 字节合成 Swift。超时通过临时插件给一次真实扫描提供已过期 deadline 注入；异常也仅在临时插件注入。这验证故障路径，不是自然负载性能测量，注入代码不进入安装包。

| 场景 | 验证结果 |
| --- | --- |
| 正常 Write | 文件写入，正常收到后续请求 |
| Write 输入超时 | 不写文件，拒绝原因保留，新安全消息经自检恢复 |
| 超时后先提交敏感输入 | 敏感输入不外发、不解锁；后续安全输入可以恢复 |
| 超时后磁盘配置损坏 | 当前规则快照继续检查敏感输入并支持安全恢复，不自动加载新配置 |
| 超时后健康探针失败 | 自动恢复与手动自检均失败，继续保持故障 |
| 输入字节数超限 | 不自动解锁；手动检查后新安全消息可以继续 |
| 检测异常 | 不自动解锁；手动检查后新安全消息可以继续 |

同一超时注入还使用已安装的 0.2.0 做修复前对照：复现通用取消提示、下一条安全消息仍被阻断、原 Write 没有执行。0.2.1 的拒绝历史不再包含 `Nothing refused it`，所有恢复场景均没有重放旧 Write。

其余验证：核心与 CLI 测试 2,683 项通过；恢复相关原生 Mods 测试 27 项通过；已有真实请求恢复矩阵 26 项通过；Rust release 模式 17 项通过；插件验证通过。Rust debug 模式有 6 个规则校验测试返回 `RULE_CONFIG_REJECTED`，按项目 CI 使用的 release 模式重跑全部通过。纯状态测试额外覆盖旧工具/子代理尚未结束、非可信来源、其他故障、上下文污染及旧轮次身份隔离。

完整原生 Mods 套件并非全绿：第一次运行 151 项中 6 项因大段文本扫描超出预算失败；针对受影响文件串行重跑后，仍有 2 项失败，分别是共享提取器混合字段耗时测试和重复密集源码完整路径测试。失败表现是结果被超时扣留，没有提前释放。没有调整扫描预算或放松断言来使这些测试通过。新恢复路径解决故障后的可解释性与继续条件，并不保证高负载下大文本不再超时。

## 边界

这些证据不覆盖所有桌面版本、所有后台子代理或远端 MCP 的完整请求路径。插件缺席、被禁用或宿主不等待插件时的行为不能据此声称失败关闭。健康探针不证明历史已清洗，也不撤销已执行工具的副作用。对原始输入保存到本地历史、工具直接联网等原有边界，参见 [脱敏与恢复说明](recovery-redaction.md)。
