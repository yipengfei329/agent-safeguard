# 实施与验收计划

产品约定以 [一期设计](v1-design.md) 为准。首版运行时和合成回放已实现，当前证据与剩余发布门槛见 [验收报告](acceptance.md)。下列项目是完整目标，不表示全部已完成。

## 1. 验证接入能力

- 确认本机 Mods 的加载条件、接口类型和插件顺序。
- 创建最小测试插件，先在隔离目录通过 --plugin-dir 加载。
- 用虚构标记验证工具参数拒绝、成功结果扣留与错误结果扣留。
- 确认异常和超时处理，检查调试日志、会话记录及恢复后的行为。
- 检查实际发送给模型的内容；界面隐藏不算通过。
- 使用隔离本地模型响应桩验证命中后无后续请求；验证 turn.step 与停止 API 的并发、子代理和异常路径。
- 先证明接口足以支撑保护范围；本机普通用户 Mods 不以引擎 http.fetch 作为已可用控制点。

## 2. 实现本地规则引擎

- 第一批规则：指定敏感值、IP 地址与 CIDR 网段。
- 将“全部 IP”与“指定 IP/网段”作为可区分的策略。
- 遍历结构化文本字段；明确图片、附件及其他非文本内容的处理政策。
- 整份结果命中即扣留，返回固定规则编号，不回显敏感值。
- 明确数据大小限制和异常路径，禁止截断扫描后当作安全结果放行。
- 实现配置结构和语义校验、不可变规则快照、轮次边界切换、版本回滚与虚构样本回归。
- 真实敏感值仅在用户私有配置；不自动接受仓库规则来放宽保护。

## 3. 性能与防护验收

覆盖 10 KB、100 KB、1 MB 及更大输出；命中在开头、末尾和完全不命中；少量和大量规则；多个并行工具调用。

初步端到端延迟预算：10–100 KB 输出 p95 ≤ 5 ms，1 MB 输出 p95 ≤ 20 ms。这些是设计目标，尚无实测。比较启用与未启用插件的同一负载，分别记录插件调度和扫描成本。

用测试矩阵验证内置工具、MCP、子代理、失败返回、超时、恢复会话和插件缺失。真实敏感数据不用于验收。

## 4. 安装与发布

接入和性能验收后，再提供用户范围安装的本地 marketplace、状态检查和卸载说明。首版不需要开机启动服务。

只有测量结果支持时才评估 Rust。图形管理界面在核心能力稳定后考虑。

## 5. 桌面管理原型（历史基线）

按当前产品方向增加独立 Rust + GPUI Kit 管理端，不改写既有 JavaScript 检测器，不把管理窗口接入扫描必经路径。

- 已实现原型：Claude 用户范围插件安装/更新/启用/禁用；会话状态 JSON 的手动快照展示；规则 JSON 编辑、原引擎校验、备份和回滚。
- 当前状态页不是实时监控；其他 harness 仅检测可执行文件。在线更新源、实时状态通道、运行中规则热切换不在本次实现中。
- 本轮先验证本机 macOS Release 安装包、启动和进程树 RSS，Windows/Linux 构建、安装器和真机验收仍待完成。
- 复现步骤见 [桌面原型说明](../desktop/README.md)，数据与边界见 [原型测量报告](desktop-prototype.md)。

## 6. 桌面一期实现（0.2.0）

页面范围见 [桌面一期功能与页面设计](design/desktop-v1.md)。已实现概览、工具、规则三页，本机 Claude Code 安装、自动状态上报与基础规则表单已通过隔离流程测试；保留现有检测引擎，校验运行时内嵌。按最新反馈采用 Linear 风格的深色紧凑布局。在线发布源、Windows/Linux 安装器和跨平台真机验收仍是发布门槛，详见 [桌面一期验收](desktop-v1-acceptance.md)。
