# 模拟器设备标识

0.1.16 修复开发测试日志中模拟器 UUID 被当成真实设备标识的问题。不关闭设备检测，不根据命令名、测试目录、模型名、设备名或整段日志中的 Simulator 字样放行。

## 范围

- 同一设备对象直接包含 `platform`，值须精确等于 `iOS Simulator`、`tvOS Simulator`、`watchOS Simulator`、`visionOS Simulator` 之一。
- 仅放行该对象直接包含的 UUID 格式 `deviceId`、`device_id`、`device-id`、`udid` 字符串。数组/子对象不继承该例外；序列号、硬件 UUID、MAC 和主机名照常检测。
- 结构化结果与 JSON 按对象作用域处理。日志中的完整 JSON 设备对象可带 grep 的 `7:`、`8-` 或文件名/行号前缀。代码中的 UUID 引用不会自动获得例外。
- 对日志仅遮盖已确认的字段值供设备规则检查，其他规则仍扫描原文，精确匹配指定 UUID 仍能阻断。相同 UUID 在相邻真实设备或嵌套子对象中出现时仍被检查。
- 同一内容中的凭据、国内 IP、真实设备信息仍可导致整次工具结果被扣留。放行测试日志不会修复测试自身失败，也不撤销已执行操作。

这是对本地工具提供的元数据进行分类，不能认证它的真实性。没有标记、标记不明确、截断、格式损坏等情况保留原设备检测行为。JSON 转义和解码受现有嵌套次数限制；文本记录最大 64 KiB、对象栈深度最大 64，超出不增加豁免。整体扫描预算仍为 100 ms，异常和超限处理不变。

## 验证

公开样本全部为合成设备，不复制用户实际设备 ID、源文件或会话内容。`tests/simulator.test.mjs` 验证多种包装/来源、grep 输出、混合真实设备、重复 UUID、嵌套记录、不完整记录、自定义精确规则和相邻凭据。`tests/simulator.test.ts` 验证原生插件的工具结果及后续模型步骤。

```sh
npm test
npm run test:mods
python3 scripts/e2e.py
SAFEGUARD_TEST_INSTALLED=1 python3 scripts/e2e.py
```

本机 Claude Code 2.1.325 原生完整检查链路测量：6 条启用规则，每组预热 5 轮再测 20 轮。包含密集模拟器 JSON 和 grep 行号的 10 KiB 输出，单并发 p50/p95/p99 为 1/2/2 ms；100 KiB 为 9/9/10 ms。4 并发时 100 KiB 为 32/34/34 ms。数值包含宿主分发与其他规则，不是单次查字段的微基准，也不代表所有机器的性能保证。

本轮核心测试 1,662 项、原生 Mods 测试 64 项、桌面 Rust 测试 14 项、Node/桌面规则校验一致性 10 项，以及隔离 CLI 请求用例 63 项全部通过。CLI 请求用例中，明确模拟器日志产生第二次请求，真实/混合设备、序列号或凭据结果只产生初始请求。以上请求只发往本机模拟服务。

本机已安装插件 0.1.16 的 44 项端到端用例通过，包含结构化模拟器、grep 模拟器日志放行，以及真实设备、混合设备、相邻凭据和序列号阻断；插件缓存与构建文件一致，更新没有改写用户规则。已有会话需重启或新建后生效。
