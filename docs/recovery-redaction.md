# 工具结果脱敏与会话恢复（0.2.2）

本版实现可选择启用的 IP 结果脱敏和拦截后恢复，桌面管理端版本为 0.3.2。已有 schema 1 配置继续使用会话锁定策略；升级二进制不会静默迁移用户规则。实现对应[已批准方案](design/redaction-and-recovery.md)，下文明确本版收窄范围及验证边界。

## 行为

| 遇到的情况 | 本版行为 |
| --- | --- |
| 没有命中 | 返回原结果 |
| 支持的同步 Bash 诊断输出，只命中 IP 脱敏规则 | 本地替换为 `[IP_1]` 等代号，重新检查后返回，并说明代号不能用于连接或配置 |
| 原工具执行失败且错误文本可以脱敏 | 返回脱敏的错误，保留工具失败状态；不暂停会话 |
| 同时命中凭据、设备标识、自定义 block 等 | 扣留整份结果，暂停当前轮次 |
| 源码/命令特征、含敏感 JSON 键、重复键、格式不明确 | 放弃脱敏，扣留结果 |
| 非 Bash、图片混合、后台/持久化输出及未知 Bash 字段需要脱敏 | 扣留结果，等待后续适配验证 |
| 输入消息命中规则 | 拒绝当前消息；修改后可再次发送，不因普通输入命中永久锁定 |
| 单次扫描超时 | 保持故障状态；旧工作结束后，新可信消息通过检查并完成本地自检，才允许恢复 |
| 扫描异常、超限、脱敏资源耗尽 | 保持故障状态，普通新消息不能清除 |
| 已暂停且旧轮次、调用、子代理均结束 | 下一条通过检查的可信入口消息可继续原会话 |
| 后台通知、插件/同伴注入、来源缺失、meta 消息 | 不能触发恢复 |

新消息恢复不会重放被扣留的结果，不会自动重跑命令，也不撤销之前已完成的操作。模型已经知道的内容无法撤回。

## 配置与迁移

安装或更新至插件 0.2.0 后，从自己的当前规则生成草稿。以下示例不读取或展示私有值：

```sh
# 仅启用恢复，保留所有拦截动作
npm run rules -- migrate /absolute/path/to/current-rules.json local/recovery-draft.json

# 同时将所选 IP 规则的工具结果部分改为脱敏
npm run rules -- migrate /absolute/path/to/current-rules.json local/redaction-draft.json --redact network.address
npm run rules -- validate local/redaction-draft.json

# review 后保存，新插件实例生效
npm run rules -- apply local/redaction-draft.json --user
# 需要时回滚上一份规则，新实例生效
npm run rules -- rollback --user
```

草稿使用独占创建和 0600 权限，不覆盖已有草稿。迁移保留检测范围、CIDR 豁免、工具范围、enabled、其他规则及限制。跨输入/输出的 IP 规则拆成原输入 block 规则和 `.output` 结果 redact 规则；原输入规则 ID 保留。ID 冲突、超过规则上限或不支持的选择会被拒绝。CLI 与桌面使用同一迁移实现。

桌面“规则编辑”提供“生成安全恢复草稿”和“生成恢复与 IP 脱敏草稿”。后者选择当前所有包含工具结果的 IP block 规则；保存前显示动作和恢复策略摘要，保留上一版与自定义名称。保存 schema 2 前要求安装源插件至少 0.2.0。该检查不是对每个运行中实例或缓存版本的证明；应更新插件并在新实例查询 `/agent-safeguard-status` 的版本与就绪状态。

`config/redact-results.json` 是合成示例，不是替换个人规则的迁移工具。其 IP 国家/豁免策略与原工具结果示例一致，未命中的 IP 不会一律打码。

schema 2 要求明确 `policy.recovery`：`next-safe-user-prompt` 或 `session-lock`。`redact` 目前只允许 IP 检测器且来源恰好为 `tool.result`。输入检查不做脱敏，不改写将要执行的工具参数。

## 恢复步骤

1. 普通拦截后等待当前轮次结束；状态中 `canResume: true` 表示本实例已具备恢复条件。
2. 发送例如“跳过刚才的输出，检查构建是否成功”。新消息本身通过检查后，新轮次开始。
3. 单次 `inspection.timeout` 可以由下一条安全可信消息触发本地自检；它使用当前规则快照，不加载新配置，不重放原工具。自检失败或其他 `faulted` 情况，先解决配置或数据规模问题，再从可信入口执行 `/agent-safeguard-check`。该命令本地重新加载/编译规则并检查固定探针；成功后仍需新安全消息才能继续。
4. `context.blocked` 或上下文 hook 故障不通过普通检查解除，后续故障也不能覆盖这个门禁。修复自动上下文来源后创建新插件实例；本版不提供历史全量清洗。

健康检查不是任意历史内容的安全证明，也不绕过正在运行的调用或子代理。如果宿主没有发出结束事件，恢复会继续等待；不能把迟迟未结束解释为已安全取消。旧 schema 1 不获得这项原地恢复能力。

本机宿主将 CLI/外部控制输入标记为 `sdk`。本版明确信任 `composer`、`bridge`、`sdk` 三种固定宿主来源，但 SDK 来源不等于真人身份认证。无法提供这些固定来源的宿主不支持自动恢复。恢复后来源不明或后台注入的提示仍被拒绝，无新提示授权的根轮次自动续跑也不能开始模型推理；这可能影响后台协作工作流。

## 实现依据及范围调整

接口以本机 Claude Code 2.1.325 生成的 Mods 类型声明为准。参考官方[类型生成说明](https://code.claude.com/docs/en/plugins/mods/create)。本版没有假设存在未验证的通用结果替换接口。

- `tool.call` 没有轮次 ID。适配器在调用开始捕获实例中的轮次代际（epoch）归属，等待全部在途调用、turn.complete 与 SubagentStop 后再允许恢复；旧归属不能访问新代际。已完成 turn 的记录删除，迟到的 step 不获授权。子代理身份保留为有界记录。
- 每份原结果先接受全部 block 规则检查，阻断优先级高于任何 redact。然后定位/替换全部受保护 IP，并将替换结果及固定说明重新扫描；任一步失败均扣留。
- 原生返回值的 `ref` 指向宿主原始消息。成功替换必须构造新结果并去掉 `ref` 与原文本捷径，不能只修改用于界面显示的文字。
- 在当前宿主中，Bash 错误的字符串结果无法直接作为替换的成功结果结构返回；`isError: true` 也不足以保持状态。本版使用宿主的 `deny` 结果分支携带已经脱敏的错误文本。实测模型请求中的 `tool_result.is_error` 保持 true，且实例不进入暂停。宿主可能将其显示为插件拒绝提示；不能伪装成执行成功。
- 同步 Bash 采用明确字段集合。后台句柄、原始/持久化输出路径、结构化内容、编辑差异、截断标记或未来未知字段存在时不启用替换。普通未命中输出仍遵循原策略。
- JSON 只对值替换；键命中、重复键或无法解析的 JSON 样式文本扣留。JSON 重序列化可能改变空白和数字的文本格式，不承诺字节级格式保持。诊断与源码判别是保守词法规则，不是完整语义或 AST 分类器。
- 带行号的 Go 测试失败摘录可以保留失败详情和堆栈里的花括号。每处命中都须落在具有完整时间戳、级别、消息和地址字段的日志记录中。明确的源码、命令和其他形态的命中继续扣留。
- 同一 Bash 输出先列出 `git grep -n` 源码行，再给出带包级 `FAIL` 摘要的 Go 测试摘录时，可保留源码行并替换测试日志里的地址。源码行本身命中受保护地址时扣留整份结果。
- 标签仅在一个引擎实例内稳定，IPv4 与对应 mapped IPv6 共用标签。采用最多 4096 项的内存映射，不落盘、不提供反查，也不使用可跨实例关联的确定性哈希。内存仍持有原 IP，不能防御进程内存读取。重启、恢复为新进程或成功健康重载会重置映射；不要跨实例比较 `[IP_1]`。
- 所有阶段共享一个 100 ms 截止时间；字节/节点预算分别约束每遍遍历，**不是把多遍遍历累计成一个 4 MiB 总读取额度**。4 MiB 限制包含包装字段、键和重复文本，不能简单理解为 stdout 可到 4 MiB。超时是协作式检查，不能抢占单次同步操作。没有在扫描结束前提前返回结果。
- 上报采用 schema 3，分别记录暂停、恢复、脱敏结果数、替换次数及状态。替换次数按受检表示中的匹配位置计算，重复表示/出现分别计数，不是唯一 IP 数。每次拦截独立 recordId，避免同一会话后续拦截覆盖首次记录。队列最多 32 条，后台异步写入；队列溢出、写入失败或崩溃可能丢记录，仍不是完整审计日志。记录无命中内容、原工具输出或 IP 映射；原有会话标题/项目等本地管理元数据保留。

## 验证与发布边界

具体场景、结果和性能见[验收记录](recovery-redaction-acceptance.md)。真实模型请求回放使用临时 HOME、虚构 API key、本地 HTTP 模型桩和本地生成的样本；没有调用外部模型，没有修改用户当前插件安装。

本版真实请求证据覆盖同步 Bash、受限 Read 回退、同进程继续、落盘后 resume/fork。MCP、子代理与并发隔离主要为原生事件模拟，尚未证明所有真实后台子代理/远端 MCP 的全链路行为。压缩只验证原生 hook 暂停门禁，尚未完成真实压缩模型请求验收。Hermesh/Claude 桌面活跃会话恢复 UI 也不由 CLI 桩测试代替。

未支持的图片、PDF 等仍遵循 `onUnsupportedContent`；默认 allow 不表示内容已扫描。插件缺席、被禁用或 worker 崩溃时，宿主能否继续外发是另一层问题，不能据检测器的扣留行为声称整个系统失败关闭。用户输入即使出站被拒绝，宿主仍可能先保存在本地历史；本版不承诺清除这部分历史。工具直接联网、附件上传、其他插件/遥测和已存在的历史不在本次新增覆盖范围。

0.2.1 对拒绝提示和超时恢复的修复、实际 Write 回放及限制见 [超时恢复记录](timeout-recovery.md)。

0.2.2 分离消息提交互斥与新轮次授权，修复没有新模型轮次时残留的 `recovery.busy`。恢复后仅接受空闲边界的新消息；轮次执行中的补充或排队输入需等本轮结束再提交。此前从未暂停的初始轮次不受此新增排队限制。状态命令新增提交状态计数，详见 [提交生命周期记录](prompt-admission.md)。
