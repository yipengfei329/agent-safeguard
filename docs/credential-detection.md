# 凭据检测

当前引擎为 0.1.19。以下基础值证据继承 0.1.17；本轮调研、调整与验证见下文。配置格式和拦截动作不变，仍然扣留整份结果，不做星号替换或修改用户代码。

0.1.17 使用“字段上下文 + 具体值证据”，不再因字段叫 token/password 且字符串超过 4 字符就阻断。它是本地、有界的启发式检测器，不验证凭据是否真实有效，也不是完整语言解析器。

0.1.17 移除“无法识别的右侧表达式截取第一个词，再按秘密值评分”的兜底行为。仅在结构化实际字符串、引号字面值、已识别的透明包装、完整未加引号的配置/日志标量及显式认证格式中提取值。未知语法不能以标点和长度为依据触发凭据判断。

## 判断顺序

1. 私钥头、带密码的认证 URL、已支持的 Anthropic/GitHub/Slack Token 格式及 JWT 形状独立检查。这些显式认证证据不依赖通用熵阈值；例如认证 URL 中的短密码仍拦截。
2. 类型声明、代码引用、延迟变量替换、明确遮盖和常见占位符不构成具体秘密值。支持 Rust `pub`/`pub(crate)`、引用/生命周期/泛型、Swift/TypeScript/Python 等常见声明。仅排除当前表达式，类型后的初始化值、相邻字段继续检查。
3. 普通凭据字段必须同时有像秘密值的实际内容。`String`、`Bool`、`config.token`、`getSecret()`、`simulator`、`123456` 不再仅凭字段名阻断；结构化对象与文本使用同样证据标准。
4. 通用值采用长度、字符类别和 Shannon 熵组合，不对所有代码/哈希/随机字符串做全局熵拦截。密码字段达到 8 字符、3 类字符、熵 2.5；其他通用候选达到 12 字符、2 类字符（含数字或符号）、熵 3.0，或达到 24 字符、熵 3.5，才触发这条判断。还须先通过类型、引用、占位符等排除检查。熵只采样前 256 字符，每个字段的上下文工作有界。
5. JSON 里的凭据按解码后的值检查，避免转义引号增加长度和字符类别而产生误报。其他规则仍保留原始文本匹配语义；嵌套解码次数和扫描预算不变。
6. 支持常见透明值包装（Swift `.string`/`.some`、Some、String::from、SecretString::new、Buffer.from 等）及有界的直接字符串拼接。一般函数调用的参数可能只是环境变量名，不无差别视为密钥。

这意味着短密码、普通单词组成的弱密码，以及不符合已支持格式的短 Token 可能放行。这是本次“优先降低误报”的策略选择，不能宣称仍覆盖所有真实密码。需要强制保护的特定值可继续配置 `exact` 规则。

没有按测试文件、注释、`test`/`example` 路径或测试开关整段放行；测试代码旁边的高置信凭据仍然拦截。保留所有 IP、设备和其他自定义规则。

## 迭代与验证

规则启停、来源、工具范围和精确值通过 JSON 配置管理；值证据和语法识别属于引擎版本升级。公开测试只使用合成样本，不保存用户文件或会话内容。

- `tests/credential-confidence.test.mjs`：不同语言的声明、泛型、引用、JSON 转义、占位符、错误输出、模拟 Edit 全文件返回，以及相邻秘密值反例。
- `tests/credential-expressions.test.mjs`：未知表达式、Swift 值包装、不同输入来源与嵌套输出，并在每类放行样本后追加具体秘密值验证仍能阻断。
- `tests/credentials.test.ts`：原生插件返回/阻断和后续模型步骤，含密集 Rust 声明性能测试。
- `scripts/e2e.py`：隔离 HOME、虚构凭据、本地模型 API；确认正常结果产生第二次请求，阻断结果不提交后续请求。
- `credentialReason` 只返回原因分类，不返回命中原文；分类不等于确认凭据有效，也尚未接入桌面日志。

```sh

```

## 生效与边界

已有会话持有旧引擎，必须重启或新建 Code 会话。升级保留用户规则，使用 `pluginVersion` 确认更新。工具结果拦截不撤销已经执行的编辑/命令，也不涵盖工具自己发出的网络请求。

100 ms 扫描预算、文本大小/深度限制和异常阻断不变。动态拼接、任意编码、陌生格式、无敏感字段上下文的密码和复杂/不完整语法仍可能漏检。不能通过本工具推断账号封禁原因。


0.1.17 验证（Claude Code 2.1.325）：1,746 项核心用例、67 项原生 Mods 测试、14 项桌面后端测试及 10 项双引擎验证用例通过。原生完整调用链、6 条启用规则、单并发，20 个预热后样本：100 KiB 密集 Rust 声明 p50/p95/p99 为 8/9/9 ms；1 MiB 为 62/64/65 ms。没有放宽原有 100 ms 检查预算。这些是本机样本，不保证所有输出或负载均低于预算：启用状态上报时，1 MiB、4 并发的完整调用路径 p50/p95/p99 为 137/169/197 ms，包含排队和上报开销。

0.1.17 的 66 项隔离端到端测试和 47 项安装版端到端请求测试通过：Rust 声明、Swift `.string(key)` 和未知表达式继续产生后续模型请求；`.string("高置信测试密钥")` 则只收到初始请求，未提交后续工具结果。仅使用本机模拟模型服务。实际误拦文件的私有回放也已放行，其内容不进入公开测试或报告。

未加引号的标量只接受受限字符集和明确值边界；复杂未加引号密码和未知函数中的普通字符串可能放行。明确 Token 格式仍在全文检查，自定义 exact 规则仍可保护指定值。该策略不能验证凭据是否有效。

## 0.1.19 调研与方案选择（2026-11-15）

问题在于值的身份和用途，而不只是熵阈值。旧实现能够跳过部分变量和类型，但仍把字符串字面量类型、UI 提示、常规字段标签、文件路径等送进秘密值评分。相反，靠近类型声明的注释又可能被当成代码引用，漏掉其中的实际值。

调研直接阅读了项目文档、规则实现和论文。没有下载含真实泄露凭据的研究数据集，也没有向第三方验证任何候选值。

| 来源 | 可借鉴的方法 | 本项目采用方式与约束 |
| --- | --- | --- |
| [Gitleaks generic rule](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/generate/config/rules/generic.go) | 提取秘密分组，再应用熵、字符形态和误报过滤；服务商规则独立 | 采用候选值级负面证据，不照搬整行、文件白名单；它的通用规则字符集与本项目密码范围不同 |
| [Yelp detect-secrets](https://github.com/Yelp/detect-secrets/blob/v1.5.0/README.md)、[过滤器实现](https://github.com/Yelp/detect-secrets/blob/v1.5.0/detect_secrets/filters/heuristic.py) | 插件检测与过滤分离，处理引用和模板；设计中仍有人工审核 | 拆分值分类和语法提取；不采用全局 UUID / 文件类型豁免，不把可疑结果直接等同于可用凭据 |
| [TruffleHog](https://github.com/trufflesecurity/trufflehog) | 区分 verified、unverified 等结果，服务商验证提高确定性 | 只作为设计参考；对外发送候选值验证不符合本地扫描要求，不能以未验证为由放行 |
| [CredSweeper 架构](https://credsweeper.readthedocs.io/en/latest/overall_architecture.html) | 预处理、候选扫描、算法过滤、可选 ML 判断分层 | 借鉴分层，暂不引入模型运行时；未经本机延迟、内存及分布外测试的模型不进入同步阻断路径 |
| [Semgrep Secrets](https://semgrep.dev/blog/2023/introducing-semgrep-secrets/) | 语义与数据流信息辅助区分变量用途 | 明确类型和初始化值的区别；当前实现只是有界词法识别，不冒充跨文件数据流分析，也不把其商业 Secrets 能力等同于可直接嵌入的开源库 |

[SecretBench（MSR 2023）](https://arxiv.org/abs/2303.06729)提供跨语言标注数据，说明应同时测误报与漏检，而不是只数测试通过数量。[Secretron / StringGroup（ISSTA 2026）](https://arxiv.org/abs/2608.04523)研究字符串及局部上下文的价值；其论文结果不能直接推算到我们截断、混合格式的工具输出。[2026 年的数据泄漏研究](https://arxiv.org/abs/2601.22946)指出重复或近重复训练/测试样本会夸大检测指标。因此，本轮不以论文 F1 或本项目回归集零误报宣称生产准确率。

### 实现

检测链保持本地 JavaScript，不增加 Python/Go/远程服务运行时依赖。调研对照工具仅装在 git 忽略的 `local/research/`，生产插件不调用它们。

选型还受实际入口约束：当前 Mods 构建要求单模块不超过 1 MiB，扫描有 100 ms 协作式预算，而且输入常常是 grep、补丁、错误输出和截断片段，未必是可交给编译器的完整文件。本轮没有实测 CredSweeper 模型或完整多语言 AST 的本机开销，不能声称它们已经满足这些限制；后续引入须先做独立样本与运行时验证。

1. `credentials.js` 负责字段上下文和具体值提取；显式 Token 格式、私钥头和认证 URL 始终独立检查。
2. `type-context.js` 对完整 TypeScript interface / 对象类型声明做词法识别，只返回字段 token 的偏移。注释与字符串不能打开类型作用域；不完整声明不授予例外。字段之后的初始化值、相邻字段、注释仍检查。共享身份检测也使用这个类型判断，但真实 hostname / device_id 值不因此放行。
3. `credential-values.js` 负责具体值的负面和正面证据。新增完整值级的模板、常规标签、MIME、可读路径/无认证 URL、简单正则形状和受限 UI 提示语判断。非密码字段里的小写分隔单词标签降低置信度；不对任意随机串、UUID、测试文件或含有 `example` 的字符串整体放行。
4. 引号解析同时返回解码后的值和消耗的原始字符数，避免反斜线增加熵，或解码后长度变化导致拼接位置错位。支持常见转义，不承诺任意语言字符串语义。
5. 单次文本检查内分别缓存密码和其他字段最多 128 个、长度不超过 256 的否定值判断，减少重复枚举和标签的开销；不跨扫描持久保存内容，不缓存整行/文件放行。词法过程参与现有协作式预算。

没有降低原有熵阈值或放宽 100 ms 扫描预算。类型识别和标签过滤是降低误报的策略：真实密码若恰好等于被识别的标签、占位符、路径或提示语，仍可能放行；未知语法、片段和未支持 Token 格式也可能漏检。已知必须保护的值应使用 `exact`。未接入通用 AST、多语言数据流、模型分类或服务商在线有效性验证。

### 可复现对照

`fixtures/credential-corpus.mjs` 在实现改动前建立 39 个正常场景和 36 个应阻断场景，全部是人工标注的合成内容。新增测试再覆盖四种包装、四个来源、相邻凭据、注释、错误文本、字面量初始化及局部例外边界。额外 16 个离线生成的格式探针用于确认对照工具的扫描与规则实际生效。

同一批文件实测 Gitleaks **v8.30.1** 默认规则和 detect-secrets **v1.5.0** 默认插件，后者显式使用 `--no-verify`。没有基线忽略文件或自定义白名单。

| 实现 / 配置 | 正常场景误报 / 39 | 应阻断场景未报告 / 36 | 独立格式探针报告 / 16 |
| --- | --- | --- | --- |
| Agent Safeguard 0.1.17 | 27 | 1 | 16 |
| Agent Safeguard 0.1.19 | 0 | 0 | 16 |
| Gitleaks v8.30.1 默认 | 0 | 33 | 16 |

**这是项目回归对照，不是通用工具排名，也不是独立盲测。** 新实现使用了这些样本迭代；36 个阻断场景多次复用同一个带标点的合成秘密，另有私钥头、不满足其他工具完整格式或熵要求的模拟 Token。Gitleaks 对通用值字符集、完整服务商格式及熵的要求不同，因此多数“未报告”不能解释为其真实凭据召回率很低。16 个格式探针中 Gitleaks 全部报告。结论仅为：不能把某个离线扫描器的默认输出直接替换当前在线阻断策略；也不能只通过关闭通用检测来消除误报。

### 性能与请求路径

Claude 原生测试框架，6 条启用规则，密集类型/提示语/标签混合输出；每组预热 5 次后测 20 轮。4 并发组共 80 个调用样本，数值含插件事件分发与排队，单位 ms：

| 输出大小 | 并发 | p50 | p95 | p99 |
| --- | --- | --- | --- | --- |
| 10 KiB | 1 | 2 | 2 | 2 |
| 10 KiB | 4 | 5 | 6 | 9 |
| 100 KiB | 1 | 9 | 13 | 15 |
| 100 KiB | 4 | 36 | 53 | 69 |
| 1 MiB | 1 | 85 | 87 | 92 |
| 1 MiB | 4 | 345 | 356 | 358 |

首次性能验证发现 1 MiB 密集输出触发预算，随后加入候选值局部缓存并复测通过；没有提前释放未扫描的结果。并发耗时不是单次扫描预算，超过 100 ms 的排队时间不能视为预算被放宽。这组重复标签负载能受益于缓存，不代表全是不同值的文件也有相同性能；超限依旧阻断。

最终验证：2,067 项核心测试、75 项原生 Mods 测试、14 项桌面后端测试通过。开发目录 72 项本地请求用例通过；最终安装版 54 项通过，包含最后追加的正则/类型边界用例。正常类型与标签输出产生第二次模型请求，相邻凭据、stderr、注释、类型初始化值和正则边界用例均仅产生初始请求。所有请求使用隔离 HOME、合成数据和本机模型桩。

本机插件已更新为 0.1.19，登记的安装缓存内容与构建产物一致，用户规则文件摘要未变化；已有会话需重启。桌面管理应用的可分发安装包未在本轮重新发布。插件结构校验通过，现有公开目录图标/本机忽略文件警告不等于发布验收通过。完整数字与范围见 [机器可读记录](credential-precision-measurements.json)。

## Magpie 实现对照（2026-11-15）

审查版本固定为 [b4968d444580629646c3c71dca3c871cf674142a](https://github.com/yetone/magpie/tree/b4968d444580629646c3c71dca3c871cf674142a)。本轮阅读了检测器、协议转换、响应还原、本地模型适配和网关错误处理代码，并执行纯规则模块的合成样本探测。没有启动其网关、下载模型、修改代理配置或调用外部凭据验证。本节是研究结论，不表示下列建议已进入生产插件。

### 实际架构

Magpie 位于模型 HTTP 网关出口。请求内容先识别敏感片段，再以稳定占位符或同形替代值发送；返回内容中的占位符还原为本地原值。它支持按类别 mask / warn / block。Agent Safeguard 当前位于 Claude Mods 的事件路径，主要操作是拒绝输入或扣住整个结果，命中后维持阻断状态；没有占位符还原协议。因此，Magpie 的低打断体验来自不同的处置方式，不能据此推断它的识别误报更少。[网关入口](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/gateway/redact.go)、[替换与动作](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/redact/redact.go)。

检测由数层组成：

- 服务商格式规则，覆盖 GitHub/GitLab、Google、AWS、Stripe、Cloudflare、Hugging Face 等；另有私钥、认证 URL、Authorization/Cookie 和通用字段赋值规则。通用值判定仍有启发式，例如 `secretValue` 要求同时出现字母和数字，不能覆盖所有密码形态。
- 候选值及上下文过滤：代码引用、函数名、文件行号、路径、包版本、时间戳、空赋值后的下一字段。不是看到字段名含 token 就一定替换。相关过滤见 [fieldvalue.go](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/redact/fieldvalue.go)。
- 可选个人信息与自定义词条、正则，以及本地模型。当前代码提供约 39 MB 总下载量的 AstrLink Guard，以及约 1.6 GB 的 Privacy Filter GGUF；前者是新用户默认模型选择。自动模型策略和显式开启不同，不能只按 README 概括为单一模型。[模型选择与文件](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/pii/pii.go)、[AstrLink 文件清单](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/pii/astrlink.go)。
- 模型输出还要检查分数、跨度、字符边界、代码与包名等上下文；它不是一个能自动消除代码误报的通用分类器。[model.go](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/redact/model.go)。
- 已替换过的值进入有界内存索引，后续脱离字段上下文出现时仍能识别。这是为了避免本地还原后的内容在下一轮历史中重新暴露。该缓存跨请求，最短已知值匹配长度为 8，有容量淘汰；不能视为永久或完整的敏感值数据库。[known.go](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/redact/known.go)。

### 协议与失败边界

它区分协议元数据、工具定义和工具参数。模型 ID、调用 ID、签名等协议值通常保留；工具定义主要扫描描述；工具参数中的同名字段按用户数据处理。带签名的模型块保持原样。这能降低协议破坏，但也是扫描范围的例外，不能宣传为所有请求字节都经过敏感内容识别。尤其不能把这些例外照搬成我们的全局 `id` / `name` 白名单。[json.go](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/redact/json.go)。

响应还原处理 SSE、跨块占位符和 JSON 工具参数转义；响应包装器对二进制和非 identity 编码有直通路径。若我们以后实现替换，必须同时验证还原、并发、断流、进程重启、历史压缩、签名块和未知占位符，不能仅做一次字符串替换。[writer.go](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/redact/writer.go)。

失败策略必须分开描述：

| 情况 | 审查版本的实际行为 |
| --- | --- |
| 当前请求需要脱敏，但没有 masker | 尝试刷新注册；仍缺失则返回错误 |
| masker panic / 执行失败 | 包装为错误；已审查的主网关调用点返回，不继续发送 |
| 本地模型尚未下载完成 | 规则先工作，不等待下载 |
| 模型扫描超时或只完成部分文本 | 保留已完成部分的模型结果，其余使用规则，允许继续 |
| 显式启用模型后发生模型故障 | 错误上抛并阻断；自动模式的模型故障可退回规则 |
| 脱敏关闭、指定原文路由等策略例外 | 可按配置发送原文，不属于检测失败 |

模型等待预算默认 2 秒，显式开启通常 15 秒；处于积压状态时可回到较短预算。这与本项目 100 ms 协作式检测预算及超限阻断原则不同。网关控制增强了插件缺失时的防护，但不能由此推导“任何检测未完成都失败关闭”。依据：[masking.go](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/masking/masking.go)、[注册与异常处理](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/gwmw/gwmw.go)、[主网关调用点](https://github.com/yetone/magpie/blob/b4968d444580629646c3c71dca3c871cf674142a/internal/gateway/gateway.go#L2840)。这些为源码结论，未完成其实际网络路径验证。

### 对本项目的改进顺序

1. **先细化上下文和解释。** 保持现有字段级提取，补充包清单、时间元数据、文件行号、空赋值等独立合成样本，再决定是否加局部例外。不要将“像时间戳/版本号”全局等同于非密码。命中记录区分显式格式、字段字面量、精确规则及错误原因；不记录值片段。Magpie 的 `Hint` 会留下首字符或短前缀，我们不采用这个日志策略。
2. **扩展高确定性服务商格式。** 优先增加目前显式签名未覆盖的格式，并分别验证独立出现、普通代码相似串、截断值和相邻秘密。现有 16 个探针中 8 个带字段上下文，另 8 个仅覆盖 GitHub/Anthropic 裸值；全部命中不代表我们已支持其他服务商的独立裸值。规则应预编译，并重新测完整拦截路径。
3. **明确保护状态。** 把“启用且扫描完成、无命中”与“插件未加载、被禁用、内容不支持、预算失败”区分。检测器内的超时阻断不能替代宿主对插件缺失的处理；如果需要覆盖这类故障，需控制实际请求出口。
4. **模型先做离线影子评估。** 约 39 MB 的模型值得评估，但尚未测本机加载、内存、吞吐、误报和漏检；不要直接接入同步阻断，也不复制其模型未扫完便退回规则的策略。模型不能仅凭低分推翻高确定性规则。
5. **替换并还原作为独立功能设计。** 它能减少整段工具结果被扣住，但需明确出口控制、会话隔离、占位符映射生命周期、碰撞处理、历史回放及流式还原。已知值缓存适合该功能，现有命中即阻断流程的收益有限；误报值进入缓存还会扩大误报。当前不把 Magpie 作为运行时依赖，也不直接改成网关模式。

本轮只补充研究记录；没有修改、安装或发布新的生产检测版本。

## 第一批规则优化落地（0.1.20）

在上述研究之后，经用户确认实施四项本地规则改动，没有引入模型或新增服务商规则：

1. **赋值边界。** `PASSWORD= HOST=demo-service` 按空 shell 赋值和下一字段处理，仍继续匹配后续凭据。只对无空格的 `NAME=` 形式应用此边界；引号内容、`PASSWORD = NAME=value` 和 YAML 冒号值不因此放行。设备和主机字段共用提取器，也覆盖这一边界。
2. **字段角色。** `credential-fields.js` 对 snake_case、连字符和 camelCase / 缩写词拆分后判断结尾角色，覆盖 `DB_PASSWORD`、`serviceApiToken`、`servicePrivateKey` 等。`token_count`、`passwordLabel`、`access_token_expires_at`、`notpassword` 不因包含敏感字样就成为凭据字段；显式 Token 格式与精确规则仍独立生效。保留原先支持的 `apikey` 等完整词拼写。不把普通 `key`、`public_key` 作为密码字段；未知命名和超过 256 字符的字段名不保证识别。
3. **混合模板。** `${...}` / `{{...}}` 不再让整个值获得例外；固定片段各自按原有证据阈值判断，不跨未知变量拼接。纯引用和缺乏证据的短固定片段继续放行。扫描处理平衡花括号、表达式内引号和未闭合模板，深度上限 64，参与扫描预算；不执行表达式，也不声称支持完整语言语义。裸值仅支持受限的引用语法。
4. **认证 URL。** 支持 `redis://:password@host` 中的空用户名，同时约束 userinfo 边界，不将路径中的冒号和 `@` 误作认证。URL 中有特殊分隔符的合成密码按 URI 规则编码。此轮未实现任意编码递归解码或整个 URL 语法解析。

为避免扩展字段后的性能回退，字段名先提取再分类；每段文本内最多缓存 128 个字段分类、128 个前缀语法上下文，且不缓存整行或整个输出的放行决定。移除了全局类型声明重写，改在字段处识别类型，保留原始偏移与初始化值检查。缺少相关字段词的文本跳过不必要的赋值扫描。所有缓存仅在本次文本检查内存活，检测路径没有网络或日志写入。

新增 `fixtures/credential-boundaries.mjs`：28 个正常场景、29 个预期敏感场景。0.1.19 在这批定向样本上有 1 个误报、25 个未报告；0.1.20 均符合预期。测试再覆盖四种包装、四个来源、相邻秘密、错误输出、精确规则和模板预算。这是用于修复的合成回归集，不是独立准确率评估；不意味着所有现实密码都能识别。

## 凭据材料的正向证据（0.1.21）

后续实际误报暴露出通用值判断的问题：一个引用由多个短标识符及括号、冒号组成，整串长度、字符类别和熵仍可能超过阈值。之前的策略依赖先认出每一种占位符，再排除；未知引用语法便会落入“复杂字符串就是秘密”的兜底。此次没有给特定占位符名称增加白名单，而是删除这个整串兜底，新增 `credential-shape.js` 明确判断凭据材料的形态。

- **不透明令牌。** 候选须符合常见令牌/编码的字符范围；`=` 仅作为末尾最多两个填充字符，不能把 `label=value` 当成一个编码串。满足形态后再应用长度、字符类别和熵门槛。长字母串、十六进制、编码串仍有检测路径。
- **混合字符秘密。** 在受限的实际密码字符范围内判定；密码字段保留较短强值的判断，普通 Token 字段要求更强证据。`< > [ ] { } ( ) : ; , |` 等语法分隔符不贡献这类秘密值证据。
- **密码短语。** 单独处理由至少四个词/片段组成、含字母、数字和指定密码符号的短语；普通 Token 描述文字不使用密码短语规则。删除原先任意长文本只要熵够就阻断的兜底，因此纯自然语言口令等模糊值可能放行。
- **分片判断。** 整串不符合上述形态时，仅分别检查其中的实际候选片段；不跨语法边界拼接。每个片段仍经过局部标签/引用判断。短标签不会因为外围符号增多而变成密钥；括号中若确实包含强证据秘密，仍会命中。该过程参与原有预算。
- **认证载体。** 对完整值里的 Bearer / Basic 前缀先取实际部分，再判断，补上结构化 `Authorization` 值中的这一路径；前缀本身不增加秘密复杂度。显式服务商格式、私钥、认证 URL 和用户精确规则仍独立检查。

这仍是有界启发式，不是密钥有效性验证。常见字符范围之外、过短或与普通文本无法区分的密码、未知编码和复杂引用仍有识别限制；不可把“符合某字符集”单独当作充分证据，也不可把当前测试无误报理解为通用零误报。已有类型、字段角色、完整占位符和上下文过滤继续提供负面证据。

## 统一字段值提取（0.1.22）

本次设备字段误报的根因不是某个函数名，而是不同规则走了不同的值判断路径：凭据规则已有表达式识别，设备和环境字段仍可通过 `fieldsOnly` 分支将赋值右侧任意首段文本按长度判为敏感值。因此，一个未闭合的 Python 函数调用也会被当成设备标识。此次删除该旁路，由 `assignment-values.js` 为密码、Token、设备和主机字段统一提取候选值，再交给各自策略判断。

### 判定过程

1. **字段角色。** 凭据仍使用现有字段分类；设备和环境字段保持原有配置及来源范围，没有扩大工具输入的扫描范围。
2. **先判断有没有实际值。** 函数调用、成员引用、索引、类型声明、布尔值、空值、条件表达式及动态拼接不因字段名敏感就成为秘密。支持孤立源码行、截断调用、多行赋值和常见语言声明；已知透明容器中的字面量仍提取。未知表达式不靠长度兜底。
3. **实际数据按角色判断。** 普通引号、Python 静态前缀和三引号、Rust 原始字符串、纯字面量拼接、YAML 块和受限裸标量共用提取流程。结构化字段值直接作为数据判断，不重新解释成源码：例如结构化 `hostname` 中的点分字符串仍可能是主机名。凭据继续要求材料形态及强度证据；设备标识要求常见标识/编码形态，主机名要求名称形态，电脑显示名称允许空格、括号及常见 Unicode 字符。
4. **局部跳过不影响其他规则。** 放过一个表达式不会跳过整行、整段或整个文件。嵌套敏感字段、相邻 stderr、显式 Token/私钥/MAC、用户精确规则仍独立检查。没有新增项目路径或业务函数白名单。

这是有界语法识别，不是完整 AST 或运行时求值。孤立裸标量与变量名、点分名称与成员访问存在歧义，依靠局部源码上下文区分；不支持的表达式和特殊标识字符可能无法识别，不能据此承诺所有真实数据均被拦截或永远零误报。

## 词形标签与短凭据材料（0.1.23）

本轮在通用凭据材料判断层改进两类误报，继续共用已有字段值提取器。没有按测试文件、函数、项目或具体测试值放行，也没有引入模型或词典。

- 词形标签：由 1–3 个长度为 3–20 的字母片段组成，每段为小写、大写或首字母大写，可用连字符或下划线连接；前后附加 1–6 位数字。整串不超过 64 字符。字母与短编号共同产生的长度、熵和字符类别不再视为通用 Token 的充分证据。
- 带前缀的短材料：上述词形前缀后，以连字符或下划线接一个少于 12 字符、包含字母和数字且字母大小写单一的后缀，不让前缀补足密钥材料的长度。混合大小写或更长的后缀继续原有判定；纯十六进制串不应用这项标签判定。
- 密码字段保持原有阈值：普通单词加数字可能就是用户的真实密码。设备与主机身份规则保持原有值策略。独立服务商格式、JWT、私钥、认证 URL 和用户精确规则优先于通用形态判断；局部值放行不影响相邻字段或 stderr。

这是形态启发式，不能证明一个词形字符串是英语单词，也不能验证凭据有效性。同样形态的真实短 Token 可能不再命中通用规则；必须保护的已知值应使用 exact。保留拦截测试只能证明所覆盖的合成格式，不代表所有真实密钥均可检出。

最初对用户报例的口头描述只统计了字母、数字和分隔符，误以为后缀是纯数字。复放时确认后缀实际为字母数字交错，因此补充了第二类材料边界；没有把原值复制进测试或报告。实际源码仅在本地内存复放，旧版阻断，新版通过。

## 0.1.25：名称声明与凭据值分离

修复 `Repository secret: UPPER_CASE_NAME` 等说明被误判为随机 Token 的问题。根因是提取器只交付了字符串，值分类器缺少“这里描述名称”的证据；下划线又贡献了字符类别，导致名称满足通用 Token 的长度/熵阈值。

这轮没有新增项目、文件、提供商或具体 Secret 名称白名单，也没有全局排除大写字符串：

- 共享提取器识别带冒号的名称声明语境，例如 repository、organization、environment、required、optional、variable、reference 等限定词。凭据策略只有在该语境下，才将有界的大写下划线标识符作为名称；支持数字段、前导及重复下划线和单个引号字面量。
- 普通 `secret: NAME`、`token=NAME`、JSON/结构化数据及密码值继续采用值语义。大写或出现在注释中本身不能构成放行证据。设备标识和主机名策略不使用凭据专用的名称判断。
- 完整成员/索引引用可以作为引用处理。新支持长常量名的带引号索引；任意较长字面量索引不直接豁免，仍进入原来的值/原子检测。混合大小写随机材料、十六进制材料、带标点材料不会因包在索引字符串中而被整体放行。模板引用继续沿用原有解析。
- 名称和值的负缓存分开，并按字段角色区分；候选缓存仍包含原始上下文。相同字符串先作为名称、后作为凭据值出现，仍重新按值判断。字面量拼接一律采用值语义，避免拼接出的密钥被当成单个名称。
- 共享语法分析补齐 `#` 注释识别，防止 `# const token = <material>` 被误当成代码中的变量引用。支持下划线起始的未加引号标量，保留此类实际凭据值的检查。

独立提供商格式、私钥头、认证 URL、自定义精确规则仍独立检查；名称识别不能跳过相邻字段、整行、文件或工具结果。新增回归覆盖名称和引用、普通注释值、说明语境中的随机密钥、相邻字段、拼接、缓存语境切换、结构化数据，以及凭据/设备/主机字段的跨语言引用矩阵。

这是基于语法和语境的分类，不是凭据有效性验证。若真实凭据恰好具有常量名称形状，并被写在明确的名称声明语境里，仍存在歧义；必须保护的已知值应配置精确规则。没有提高 100 ms 预算，也没有改变扫描失败时扣留结果的策略。

测量与实际安装验证见 [symbolic-values-measurements.json](symbolic-values-measurements.json)。样本全部虚构；这是回归集表现，不是盲测准确率。

本机验证：101 个虚构名称的 11312 种声明组合中，0.1.24 误报 8484 次，0.1.25 为 0；90 个普通注释凭据正例两个版本均全部拦截。原报错输出仅在本机内存中回放，修复后放行，未复制到样本。核心 2551 项、隔离运行的原生 124 项（含本轮 17 项）、串行桌面 14 项和实际安装请求 90 项均通过；名称/引用允许后续请求，注释密钥及相邻/拼接密钥均阻止后续请求。

测试记录保留了负载波动时的失败：一次原生全量运行 117 通过、7 个大输出场景失败；旧版对照也出现大输出扫描失败。桌面并行测试曾有 4 项规则校验失败，随后串行 14 项通过。隔离复测原生全量全部通过，但这不意味着任意宿主负载下都能满足墙钟预算。没有修改生产预算或删除这些回归断言。本机插件缓存已更新到 0.1.25，与构建产物一致，个人规则未变；已有会话重启后加载。
