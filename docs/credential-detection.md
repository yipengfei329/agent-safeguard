# 凭据检测

0.1.8 将单一宽泛匹配改为本地、有界的语法启发式判断。它不是完整语言解析器，也不能保证零误报或发现所有凭据。

## 判断顺序

1. 独立的高置信格式：私钥头、带密码的认证 URL、特定 Anthropic/GitHub/Slack Token 格式及 JWT 形状。不依赖字段名，不对任意随机字符串做熵拦截。
2. 结构化对象中的敏感字符串字段仍作为数据处理。例如 `{"token":"config.token"}` 仍拦截，不能用代码外观绕过。
3. 文本中的字段必须有完整边界。`ask-secret`、`my_password` 等名字不再命中字段后缀。换行后只接受明确的缩进/引号值，排除 grep 文件行号前缀，避免拼接无关行。
4. 明确的代码上下文允许类型、布尔值、变量引用及函数调用；类型后的实际字符串初始化值继续拦截。每个字段独立判断，不整行或整文件放行。
5. 普通配置/日志中的字符串值仍保守处理，包括未加引号的值、多行 YAML 值、Authorization 和常见编码构造器中的直接字符串。

仅允许明确的变量占位符与遮盖标记。没有把 `test`、`example`、注释或测试文件作为通用豁免条件；测试代码中的实际字符串密码仍可能被拦截。当前实际字符串的最小检测长度为 4，短于此值不能依赖该检测器保护。

## 迭代方式

- 规则启停、来源、工具范围和精确敏感值继续通过已有 JSON 配置管理。语法识别和 Token 格式的调整属于引擎升级，需要更新插件版本。
- 每个误报补一组最小合成用例，同时补充相邻真实凭据、结构化数据、错误输出等反例。禁止把真实用户输出或凭据放入公开测试。
- `tests/credentials.test.mjs` 覆盖提示词、工具输入、结果和上下文四个来源。`tests/credentials.test.ts` 验证原生插件事件和后续模型步骤。`scripts/e2e.py` 使用隔离 HOME、虚构凭据和本地模型 API，验证真实 CLI 的后续请求。
- `credentialReason` 只返回分类枚举，不返回命中值。现有插件日志继续记录规则编号，不记录原始内容；目前未把此分类枚举接入桌面日志格式。

## 验证

```sh
npm test
npm run test:mods
npm run validate
SAFEGUARD_TEST_INSTALLED=1 python3 scripts/e2e.py
node benchmarks/credentials.mjs
```

普通输出与含大量敏感字段名的代码需分别测量。核心微基准不能代表完整插件耗时；原生分发耗时记录在 `tests/performance.test.ts`，均为 6 条规则、单并发。并发阻断行为另由原生功能测试覆盖，不等于并发性能验收。

本机 0.1.8 验证：107 项核心测试、31 项原生插件测试、21 个安装版 CLI 请求场景通过。最后一组包含 grep 命令标签、变量引用、代码旁的密码、多行密码、看似代码的结构化数据及错误输出。正常结果产生后续模型请求；敏感结果停在首次请求，没有提交工具结果的后续请求。

原生插件分发测量（毫秒，20 个预热后样本）：

| 输出 | p50 | p95 | 样本最大值 |
| --- | ---: | ---: | ---: |
| 100 KiB 普通文本 | 2 | 2 | 4 |
| 100 KiB 密集代码 | 5 | 7 | 14 |
| 1 MiB 普通文本 | 13 | 15 | 15 |
| 1 MiB 密集代码 | 43 | 51 | 52 |

这是本机小样本结果，不是硬性延迟保证。大型密集代码在机器同时繁忙时仍可能超过既有 100 ms 扫描预算并被扣留；性能优化没有放宽这一保护预算。

## 边界

动态拼接、任意编码、陌生 Token 格式、无字段上下文的密码及复杂/不完整语法仍可能漏检。仅靠字符串启发式也无法可靠区分测试字符串和真实凭据。不能为减少误报而全局关闭凭据检测或整类源码输出检查。

升级保留用户规则，规则版本号可以不变，使用 `pluginVersion` 判断引擎是否更新。已有会话持有旧引擎，必须重启或新建 Code 会话；已阻断会话不会自动解除。工具结果拦截不撤销已执行命令，不涵盖工具自己发送的网络请求。
