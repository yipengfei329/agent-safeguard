# 模板误报与安全坐标（插件 0.2.4 / 桌面 0.3.4）

## 修复范围

token 字段中的插值模板可能把描述性前缀末尾的连接符当成凭据特征。例如，虚构代码 ``state.token = `access-token-${state.sequence}`;`` 原先命中凭据规则。现在只在插值固定片段的边界识别既有的描述性标签，不按文件名、目录、测试代码或函数名放行。密码字段、普通字符串和独立凭据格式检测保持原有语义；模板的其他固定片段以及相邻字段仍全部检查。

字段型命中现在可携带 `location: {textIndex, line, field}`。这是扫描器按遍历顺序检查的文本序号、规范化后文本内的行号，以及固定字段类别。它不是文件路径或源文件行号，不包含原始属性名和命中值。多段输出、嵌套 JSON 解码和工具包装可能改变文本序号；未提供坐标的独立格式检测不猜测位置。

引擎默认返回结构不变，插件显式开启诊断坐标。桌面报告升级至 schema 5，桌面仍读取 schema 1–4；插件和桌面应一起更新，旧桌面严格拒绝未知 schema。首次暂停原因继续保留，后续拒绝不覆盖它。

## 恢复状态与未解决的限制

恢复后任务尚在执行时提交新消息，提示由 `SAFEGUARD_PAUSED` 改为 `SAFEGUARD_WAIT [recovery.wait]`，明确说明消息没有排队，需要在当前轮次、工具和子代理结束后重发。这个拒绝表示当前入口不支持安全排队，不代表再次发现敏感内容，也不会把正在执行的安全轮次改成暂停。

自动排队没有在本版实现。核对本机 Mods 类型声明并使用临时 HOME、虚构消息和本地模型桩进行交互式 CLI 实验后，确认：

- 单次 hook 的自身执行预算为 10 秒，挂起 `prompt.submit` 等待长任务结束会触发超时；不能把这种等待作为排队实现。
- 中途提交事件有可信 composer 来源和当前 turnId；虚拟队列记录的来源变成 engine，实际投递时恢复 composer 来源。
- 入队记录与实际 prompt 行的 UUID 不同，未来 `turn.start` 没有原始 prompt UUID 或来源。不能用相同文本猜测归属，也不能将旧队列消息授权给新的恢复周期。
- 插件重新提交消息属于 plugin 来源，不能冒充新的用户恢复授权。

未来需要宿主提供贯穿入队、投递与根轮次的稳定消息 ID，以及可确认的取消/丢弃结果。届时再实现：本地检查通过后入队、按恢复周期绑定授权、暂停时使旧授权失效、实际投递时再次验证、单次消费授权、取消及容量上限。当前仍采用空闲边界的新安全用户消息恢复，不自动重放被扣留的操作和结果。

## 验证

- 核心回归 2,765 项通过，包含跨语言共享提取、相邻字面量、结构化字段、独立格式与模板矩阵。
- 原生 Mods 套件覆盖 159 项。首轮 158 项通过；运行期间更新了等待提示断言，测试副本与 hook 副本版本不同导致 1 项失败。最终 hook 与测试一起重跑恢复文件，35 项全部通过。该失败不是扫描超时。
- Rust release 20 项通过，覆盖 schema 5 坐标及未知字段/原始值拒绝。
- 真实 Claude 请求路径 7 项通过：输入拒绝、截断/完整设备数据、摘要、描述性模板、相邻凭据、不透明模板片段。每项验证同进程后续安全消息恢复。输出用例确认本地生成的虚构敏感值没有进入后续模型请求或工具历史；正常模板确实返回到模型桩。
- 原生恢复测试继续覆盖过期授权、并行结果、异常、超时、拒绝后的空闲恢复和恢复后忙碌期间拒绝。没有用自动排队实验替代这些安全测试。

上述请求路径结论限定于隔离的真实 CLI 与本地模型桩；不代表所有客户端、远端工具和未加载插件的路径均已验证。实际会话必须重载插件后才会使用新代码，磁盘安装不等于活跃实例升级。

完整原生路径基准覆盖 48 组大小、规则数量与并发组合，其中 33 组完成全部采样、15 组未完成。未完成组不报告成功分位数；100 ms 检测预算保持不变。p50/p95/p99、输出大小、规则数量和并发数见 [实测数据](template-diagnostics-measurements.json)。大输出与高并发的预算限制尚未解决。
