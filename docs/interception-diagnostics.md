# 拦截原因与恢复诊断（插件 0.2.3 / 桌面 0.3.3）

## 梳理结果

拦截不是单一状态。首次检测、同轮后续调用、已经执行的并行操作、恢复入口和历史记录需要分开表达。本版修复诊断信息，不扩大放行范围，不自动重放命令或旧结果。

| 情况 | 工具是否执行 | 处理与下一步 |
| --- | --- | --- |
| 工具输入命中 | 未执行 | 显示规则、原因及输入阶段；当前工作结束后提交新的安全消息 |
| 工具结果命中 | 已执行 | 扣留结果；明确已执行操作不会撤销 |
| 暂停后同轮后续调用 | 未执行 | `session.paused`，引用首次暂停原因，不声称这次输入命中 |
| 暂停前已经开始的并行调用 | 已执行 | 扣留迟到结果，等待全部在途工作结束 |
| 旧子代理的迟到调用 | 未执行 | `recovery.stale-owner`，不把旧身份视为新轮次授权 |
| 工具 hook 异常 | 不能确认 | 扣留结果，要求本地健康检查；不声称工具没有执行 |
| 普通用户消息命中 | 消息未提交 | 修改消息即可；原先活跃的会话不因此永久暂停 |
| 暂停后的用户消息再次命中 | 消息未提交 | 保留首次暂停原因，另记这次输入拒绝 |
| 工具扫描超时 | 依输入/结果阶段区分 | 工作结束、新消息检查通过、本地自检通过，才可恢复 |
| 资源超限、内部异常 | 依阶段区分 | 本地健康检查通过后，再提交新消息 |
| 上下文污染 | 上下文被扣留 | 修正上下文并重启；新消息不能清除此门禁 |
| 提交尚未完成 | 新消息未提交 | 等待前次提交结束；不误报为敏感信息命中 |
| 旧 schema 1 永久锁定 | 保持旧行为 | 明确需要新实例；健康检查成功也不声称已解锁 |
| 插件缺席、禁用或宿主失效 | 无法由插件保证 | 不将内部阻断等同于整个系统失败关闭 |

恢复后的轮次中提交仍受到既有入口限制。现有 Mods 接口不能可靠关联中途排队消息与未来根轮次，本版没有改变授权机制。

## 诊断与展示

- 拒绝消息包含固定的规则、原因、事件阶段及受支持工具名称。URL 密码不再只显示 `rule.match`；设备标识提示解释不完整记录无法证明模拟器平台。
- 首次暂停原因与后续关联拒绝计数分开。被拒绝的后续消息不会把最初的 Write 输入拦截改写成新的用户消息拦截。
- `/agent-safeguard-status` 增加 `diagnostic`：固定原因、下一步动作、关联拒绝计数，以及提交/轮次/代理计数。自定义规则 ID 统一显示为 `custom.rule`，外部工具名不回显。
- 桌面报告 schema 4 增加原因码和恢复建议。桌面仍读取 schema 1–3；旧桌面严格拒绝未知 schema，需要随插件升级。归档只携带对应事件的原因，不复制实时恢复建议，避免把过时建议当成当前操作指引。
- 桌面详情区分“工具未执行”“工具已执行但结果扣留”“执行状态未确认”，恢复后的历史记录也不代表当前会话仍被暂停。
- 原始命中值、工具参数/结果、异常文本均不进入新增诊断。既有本地会话身份元数据仍留在本地报告中；这不是匿名遥测，也不向外发送报告。

## 截断结构化诊断的处理

`xcresulttool ... | head -5` 等做法可能保留 `deviceId`，丢掉同一设备记录后面的 `platform`。检测器不能据工具名称或文件后缀假设它是模拟器。

应先解析完整 JSON，再投影所需字段。例如对于含 `testNodes` 的测试报告：

```sh
xcrun xcresulttool get test-results tests --path "$RESULT" |
  jq '{testNodes: [.testNodes[] | {name, result}]}'
```

这只是摘要示例，按实际报告层级选择字段。若确实需要设备记录，应保留完整记录及明确的模拟器平台元数据。相邻的物理设备、凭据和其他敏感值仍须检查，不能按项目、测试文件或示例域名整体放行。当前版本没有增加设备标识或凭据的自动脱敏；已有经过验证的同步 Bash IP 脱敏范围保持不变。

## 验证与限制

新增纯诊断、原生 hook、桌面解析和真实宿主请求回归。真实宿主脚本 `scripts/e2e-diagnostics.py` 使用临时 HOME、虚构设备和凭据、隔离插件配置及本机 HTTP 模型桩，验证：

1. 同一响应内 Write 输入被拒绝，后续 Bash 未执行；提示指出首次原因。
2. 截断模拟器记录被扣留，设备值不进入后续模型请求或工具历史；同一进程的新安全消息恢复。
3. 完整模拟器记录可通过，作为真实路径的对照。
4. JSON 摘要不携带设备 ID，检查及后续调用正常。

输入用例中的凭据由合成模型响应生成，模型本来就知道它；不能据输入拒绝声称模型从未见过该值。输出保密断言针对本地生成、模型此前不知道的虚构设备值。并行顺序和旧身份隔离另用原生 Mods 验证，不能代替所有桌面/远端工具组合。

验证结果见下方实测记录。大输出、高规则数或并发下的扫描超时仍是独立性能限制；本版不提高 100 ms 预算，不提前释放未扫描完的结果。
